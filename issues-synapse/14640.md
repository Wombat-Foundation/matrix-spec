When `/invite`ing a user over federation, the inviting server includes a bundle of "[stripped state events](https://spec.matrix.org/v1.5/client-server-api/#stripped-state)" to allow the invitee's HS to better present the invitation to the invitee's client. For similar reasons, when `/knock`ing on a room the resident HS provides a bundle of state to the knocking HS.

The spec [describes](https://spec.matrix.org/v1.5/client-server-api/#stripped-state) a list of state events that should be provided in these stripped state bundles, but notes that
- clients should check for the existence of these events
- servers are free to include new events.

The list of events to be included in Synapse is [configurable](https://matrix-org.github.io/synapse/latest/usage/configuration/config_documentation.html#room_prejoin_state), allowing admins to include a different set of event types in the stripped state bundle. In certain deployments, it would be useful to refine this selection based on the `state_key` of the events in question.
