SYNAPSE_NO_TLS behavior unexpected. SYNAPSE_NO_TLS=1 and SYNAPSE_NO_TLS=0 didn't work for federation behind a proxy-

Expected behavior: 
SYNAPSE_NO_TLS=1 works behind a proxy and is also able to support federation connections.
SYNAPSE_NO_TLS=0 works with certs in /data/homeservername.tls.key/crt with direct forwared port 8448.


Details:
I setup a new server recently and decided to try this docker file.
As I like the idea of having everything behind a proxy (with it's on cert manager), I struggled with the installation as I chosed: SYNAPSE_NO_TLS= 1.

As stated more than once, the documentation of Synapse regarding the (federation)ports, the docker config  suggests that we can disable TLS and use 8008 instead for both (second -names: entry in homerserver.yaml).

This didn't work for me from federation perspective. So I set SYNAPSE_NO_TLS=0, using the valid proxy certs also on matrix host. Also, no incoming connect.

Solution:
After removing the env variable completely it seems to work (still with some regular timeouts in the logs).


Wish:
Improved documentation about deployments behind proxies and better documentation regardings ports & tls in general. 
Let's encrypt can't be the answer for everything, as it doesn't fit in every environment.
