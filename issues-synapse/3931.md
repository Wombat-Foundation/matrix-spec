After #3842 we no longer cache `get_destination_retry_timings` database function. The rationale was that its a light query and we don't do it *that* often.

On matrix.org this seems fine, but on jki.re I'm also seeing spikes of ~100Hz, with spikes of 1s of DB time, which is a bit concerning. This seems to be due to the fact that we saturate the DB pool:

![screenshot from 2018-09-21 11-54-20](https://user-images.githubusercontent.com/8428120/45877276-2d255c00-bd95-11e8-8632-9bddb2cdc96d.png)

The database is on the same box as the synapse instance, so this is likely to be even worse for deployments where the database is on a different box.
