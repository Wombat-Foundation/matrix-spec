If I understand the FAQ correctly, the reverse proxy should connect to the unsecure synapse port to communicate over HTTP, which seems to assume the proxy is connecting locally to synapse. However, if the reverse proxy and the synapse instance are both running on different hosts it should communicate over HTTPS to make sure the communication is still secured. Otherwise the reverse proxy would be (theoretically) vulnerable for MITM and traffic between those hosts could be intercepted using packet sniffers.

I think the FAQ should be updated with the following:
 - Either the reverse proxy should be running on the same host as Synapse, or
 - The reverse proxy should connect to 8448 with a valid certificate for Synapse
