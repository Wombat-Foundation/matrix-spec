The changes in #14979 

```sql
ALTER TABLE current_state_events ADD COLUMN event_stream_ordering BIGINT;
ALTER TABLE local_current_membership ADD COLUMN event_stream_ordering BIGINT;
ALTER TABLE room_memberships ADD COLUMN event_stream_ordering BIGINT;

INSERT INTO background_updates (update_name, progress_json) VALUES
  ('populate_membership_event_stream_ordering', '{}');
```

Problems:
- the query used by `get_ex_outlier_stream_rows_txn` becomes ambiguous: there are two columns called event_stream_ordering. #14979 disambiguates this, but won't exist in old code.
- the background update doesn't add an ordering, so it might usurp other updates in the queue.

Questions:
- does the new query assume the `populate_membership_event_stream_ordering` background update has completed? How long do we expect it will take?

For 1.77 I
- reverted the PR: https://github.com/matrix-org/synapse/commit/9cd7610f86ab5051c9365dd38d1eec405a5f8ca6
- but kept in the change which disambiguates the columns in the source code anyway: https://github.com/matrix-org/synapse/commit/f10caa73eee0caa91cf373966104d1ededae2aee
- and bump SCHEMA_VERSION: #15036

For the future we should try to land the schema changes gradually (see [guidance](https://matrix-org.github.io/synapse/latest/development/database_schema.html#synapse-schema-versions)) over the next few releases.
