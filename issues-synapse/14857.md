I've spent some time on this today and now want to dump context.

- Dependabot's batch of PRs this morning all propose a big change to the way the lockfile is presented. E.g. https://github.com/matrix-org/synapse/pull/14851
- Our CI uses poetry 1.2.0, which fails to read this lockfile.
- I am guessing this is due to https://github.com/dependabot/dependabot-core/pull/6302 allowing the use of poetry 1.3.
- Poetry 1.3 introduces a new lockfile format: https://github.com/python-poetry/poetry/pull/6393
- In https://github.com/python-poetry/poetry/pull/6393#issuecomment-1255483369 it was proposed that the ability to **read** (_not_ write) the new format should be backported to 1.2.x, which happened here https://github.com/python-poetry/poetry/pull/6608

Options:

0. Stop using dependabot.
1. Ask dependabot authors if there's some way to pin the version of poetry that dependabot uses.
2. Convert to poetry 1.3.x's lockfile format. Require poetry >= 1.2.2.

I assumed that option (0) was undesirable. Put differently, I contend that dependabot is valuable to us. It does a good job of summarising what's changed in dependencies, and also automatically proposes updates when security advisories are made for our dependencies.

Option (1) seemed like a relatively big ask for a fairly small scenario, so I put that to one side. **EDIT:** The depdendabot authors seem to be aware of this problem, see https://github.com/dependabot/dependabot-core/issues/1556#issuecomment-1364366270 and the discussion following it. In https://github.com/dependabot/dependabot-core/issues/1556#issuecomment-1379373521 they point to a poetry issue https://github.com/python-poetry/poetry/issues/3316 for enforcing a minimum poetry issue, which remains open. (Note that we actually want a maximum version here).

Option (2) was my next approach. I started this process in 
https://github.com/matrix-org/setup-python-poetry/pull/14 and https://github.com/matrix-org/sytest/pull/1326. But thinking about it, I realised that anyone who wants to _edit_ the lockfile will have to install poetry 1.3.x. This includes some parts of CI (e.g. old deps, twisted trunk); so there's no way of being consistent; option(2)  is really

2'. Convert to poetry 1.3.x's lockfile format.  Require poetry >= 1.2.2 to read it, and >= 1.3.0 to write it.

but writing this down in our docs/CI  sounds like a recipe for future confusion. Instead, I propose the simpler

3.  Convert to poetry 1.3.x's lockfile format. Require poetry >= 1.3 to use it. (1.2.2 will suffice for read-only operations---but we wouldn't advertise this fact.)
