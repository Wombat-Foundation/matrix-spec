### Description

I have a postgres database with the `COLLATE=en_US.UTF-8` collation from a pretty old Synapse version, and want to migrate it to the "correct" collation `COLLATE=C`.
The dump has been created successfully, but when I'm importing the dump to the new database, I see a lot of errors (more than 50) about duplicate keys, like this:
```
ERROR:  could not create unique index "access_tokens_pkey"
DETAIL:  Key (id)=(16734) is duplicated.
ERROR:  could not create unique index "access_tokens_token_key"
DETAIL:  Key (token)=(XXX) is duplicated.
CONTEXT:  parallel worker
ERROR:  could not create unique index "account_data_uniqueness"
DETAIL:  Key (user_id, account_data_type)=(@username:XXX, im.vector.setting.breadcrumbs) is duplicated.
ALTER TABLE

DETAIL:  Key (as_id)=(whatsapp) is duplicated.
ERROR:  could not create unique index "application_services_txns_as_id_txn_id_key"
DETAIL:  Key (as_id, txn_id)=(whatsapp, 8) is duplicated.
ALTER TABLE
ERROR:  could not create unique index "applied_schema_deltas_version_file_key"
DETAIL:  Key (version, file)=(35, 35/device_outbox.sql) is duplicated.
ERROR:  could not create unique index "appservice_stream_position_lock_key"
DETAIL:  Key (lock)=(X) is duplicated.
ALTER TABLE

...
CREATE INDEX

ERROR:  could not create unique index "e2e_cross_signing_keys_idx"
DETAIL:  Key (user_id, keytype, stream_id)=(@-----------------:matrix.org, master, 1606172) is duplicated.
ERROR:  could not create unique index "e2e_cross_signing_keys_stream_idx"
DETAIL:  Key (stream_id)=(1779009) is duplicated.
...
```

This is only the start, there are more than 50 errors! 

I know that I can find all duplicates manually by composing separate SQL queries for each table and delete them, but it is a too long and hard way!

So, I'm posting an issue, because this problem is related to upgrading from old Synapse instances to the new ones with "fixing" incorrect previous collation. 

And will be good to get some script from Synapse developers, that automates finding and deleting such duplicates from the old database, to make the collation change fix working.

This could be just raw SQL queries, or maybe some script that automates the work. Is it possible to implement? 

Or maybe someone already has experience with fixing such problems, and can give advice?

### Steps to reproduce

1. Create a postgres database with non-C collation (eg `COLLATE=en_US.UTF-8`).
2. Keep it active for some months to accumulate the data in the tables.
3. Make a dump of the database using `pgdump`
4. Create a new database and try to import this dump.

You will face a lot of errors on "ALTER TABLE" and "CREATE INDEX" commands at the end of the import.
