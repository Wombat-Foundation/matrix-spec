We do hundreds of thousands of index scans of room_memberships every second, and I'm sure it can't be helpful.

I think they are coming from queries which join against `current_state_events`, and each event ends up counting as a separate "index scan".

We also get things like this in the logs:

```
2018-06-01 16:03:00,514 - synapse.storage.roommember - 87 - INFO - - Fetched room membership for !PVNuPWbpXKukMc....:t2bot.io (75492 users) in 2735 ms
```

Holding up a db thread for nearly three seconds is not a happy thing to do.

Basically, I wonder if we should be maintaining a separate table of "who is in this room right now", since that's a question we need to ask a lot (and the caches don't help that much as they get invalidated on each membership change).
