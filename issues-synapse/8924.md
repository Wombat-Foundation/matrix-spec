### Description

<!-- Describe here the problem that you are experiencing -->

Requests to /media from a homeserver are not signed. The specification requires [all requests from homeservers to be signed](https://matrix.org/docs/spec/server_server/r0.1.3#request-authentication). I understand that this is an open area of discussion in #2150, but how I read the spec currently, the requests should be signed today. One could argue, that signing requests only applies to the federation API, but requests to the media API are sent to the federation API location, not the client API location, i.e. port 8448 usually. Additionally they require `allow_remote` to be set to `false`. As such the content API is already slightly different for the federation side and in my opinion the spec text requires signatures for all requests anyway.

Signing requests to the media repository is one of the prerequisites to locking the media repository down and not allowing everyone to download media from it. While it may be useful to know, which user is requesting the media, locking out certain servers is already much more useful and probably the only feasible way to actually secure a media repo, since everything else can be circumvented by an admin anyway.

One could argue, that the spec needs clarification in these areas, but I think the current required behaviour is pretty clear. Any deviation would need an MSC. Feel free to close this, if you disagree with my interpretation of the spec or if you think the federation endpoint should not be handled differently than the client media endpoint.
