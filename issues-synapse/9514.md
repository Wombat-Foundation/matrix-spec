### Description

When upgrading from Synapse 1.26.0 to 1.27.0 or 1.28.0 (I can't figure out when the issue came up) the configuration for the OIDC provider (keycloak in my case) was changed as instructed on the upgrade file in release notes.
Since then, when i try to log in from a new device, a new account is created, instead of heaving `@user:domain.tld` I get `@user1:domain.tld` (notice the 1).

### Steps to reproduce

- Setup synapse 1.26.0 with the "old" way of configuring the oidc provider.
- Log in with one of your new account (you user gets created `@user:domain.tld`)
- Update to synapse 1.27.0 or 1.28.0 (I forgot which requires the configuration to be changed) & adapt your oidc configuration
- Log in with the same credential on a new device (old device still have an old valid state, so they continue working).
- When confirmation prompt will be `@user1:domain.tld` (notice the 1).

Expected behaviour:

- I can continue logging in with the same credential without triggering the creation of a new account.
