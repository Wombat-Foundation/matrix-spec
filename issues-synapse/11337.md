### Description

Many of our users were logged out during/after an upgrade procedure.
In the server log there were many error lines like this:

```
synapse.api.auth - 393 - WARNING - GET-0 - Invalid macaroon in auth: <class 'synapse.api.auth._InvalidMacaroonException'> 
```

### Steps to reproduce

Not sure how exactly this happened, maybe synapse was run with an empty database or a fresh config file without `macaroon_secret_key`?

Nevertheless, what should happen instead is that client do not log themselves out.
Instead, the client should either not do anything and just wait until the connectivity restores, or ask if one wants to log out.

A forced logout due to a temporary server config error should not happen.

### Version information

- **Version**: 1.46.0+bullseye1
- **Install method**: apt
- **Platform**: Debian
