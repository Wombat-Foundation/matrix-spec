The regression fixed by https://github.com/matrix-org/synapse/pull/12410 was not spotted because we annotated `args` as a `Dict[str, Any]` but then added `args["limit"]` as an `int`. This is fine because `int` is a subtype of `Any`.

https://github.com/matrix-org/synapse/blob/1a90c1e3af71fe57c5a4bce52c60e6cd7509b0c2/synapse/federation/transport/client.py#L506-L519

We pass args to `get_json`, which expects `args: Optional[QueryArgs]`, which is:

https://github.com/matrix-org/synapse/blob/bc9dff1d9597251a15a15475cb8e8194b2d14910/synapse/http/matrixfederationclient.py#L102

This isn't found by mypy because `args: Dict[str, Any]` means that we do no typechecking of the values in args.

All functions which accept `args: QueryArgs` forward args as the `query` attribute of `MatrixFederationRequest`. That attribute is typed more weakly as `Dict[Any, Any]`.

https://github.com/matrix-org/synapse/blob/bc9dff1d9597251a15a15475cb8e8194b2d14910/synapse/http/matrixfederationclient.py#L147-L149

The `query` attribute is seems to only ever be passed to `encode_query_args`. That expects a type similar to `QueryArgs`, and converts its argument list in a form that can be passed to `urlencode`.

https://github.com/matrix-org/synapse/blob/a121507cfec0ffce45a89f5a1019034eda5b0c70/synapse/http/client.py#L914-L935

We also have a `QueryParams` type elsewhere, which again is only forwarded to or passed to `urlencode`.

https://github.com/matrix-org/synapse/blob/a121507cfec0ffce45a89f5a1019034eda5b0c70/synapse/http/client.py#L100-L102

I would like to see:
- A stronger type annotation for `MatrixFederationRequest.params`
- Some unification of `QueryArgs` and `QueryParams`
- Some kind of audit of how we pass query parameters to `MatrixFederationRequest`
  - at the very least something that would have caught the regression fixed by #12410.
