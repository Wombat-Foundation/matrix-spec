So I decided to clean some non-local rooms up because the database became really huge. Purging the history takes quite a while for active rooms but the bad thing is that the entire server becomes unresponsible in the process, no rooms are working and eventually the client disconnects. As of now the server could lock up for hours thrashing the CPU. This is unacceptable of course. I understand that the database must be locked while the purging is running so it's not possible to do it in the background.

I propose splitting the whole task to smaller chunks and run them periodically one by one to allow executing the other tasks inbetween.
