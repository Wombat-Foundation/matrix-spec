I've been trying to debug memory across workers on our synapse install and we've been running with the general assumption the majority of memory usage comes from various caches. I setup a single instance in production with cache memory tracking enabled and as it turns out the jumps we see in memory are not cache:

<img width="974" alt="Screenshot 2022-08-17 at 20 52 51" src="https://user-images.githubusercontent.com/1026154/185232362-ecc3d344-7b8f-4726-a957-ae098f61cf93.png">

Note this instance is a room worker which only serves `/_matrix/client/(api/v1|r0|v3|unstable)/rooms/.*` endpoints. I'd like to understand the jump on the left, ~500mb increase in a few second window that doesn't align with any cache increase. This memory never seems to be recovered either.

We see this same pattern on other room workers (without cache memory tracking), sometimes after days of running. Once such a spike occurs GCs often jump from ~1% to 5% CPU time and the only current fix is just to shoot the worker. One example from today:
