I'm noticing that Synapse takes a very long time to complete `get_recent_event_ids_for_room` txns when handling sync requests. This seems to be most obvious when starting to sync after a period of the client being offline, as regular incremental syncs don't seem to be too affected. 

![image](https://user-images.githubusercontent.com/2072976/125906503-7ac707cc-4c2a-49ee-ba2f-6136a83c58ed.png)

The problem with this is that the txn seems to also take out my database connections:

![image](https://user-images.githubusercontent.com/2072976/125906529-2e084030-c8df-48e6-bbf5-d2b12b2bd93b.png)

I'm curious though as to why it's taking a while. Postgres isn't complaining about any one query taking too long to process (that is, more than 50s) and since I presume that sync only cares about the last N events in a room (most of my rooms are inactive as is), it can only be doing so many queries. 

This may also be related to https://github.com/vector-im/element-web/issues/16505 where Element web will spin up *concurrent* sync requests with the same sync token for reasons only it knows. My assumption is that two sync requests with the same sync token would not attempt to process the same request, but instead await the result of the previous request.
