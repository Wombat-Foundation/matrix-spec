Synapse's docker file installs a specific version of poetry in build stage 0:

https://github.com/matrix-org/synapse/blob/08297f2f18667634ad990fd4af469d6c68c70c7d/docker/Dockerfile#L58-L61

and uses it to export a requirements.txt file for the other stages to use (without having to install poetry).

https://github.com/matrix-org/synapse/blob/08297f2f18667634ad990fd4af469d6c68c70c7d/docker/Dockerfile#L78-L85

The former step is not fully reproducible[^1], because `pip` will use the latest version of poetry's build-time dependencies to install poetry. (As of poetry 1.3.2 those dependencies are the unbounded range `poetry-core >= 1.1.0`, see [here](https://github.com/python-poetry/poetry/blob/1.3.2/pyproject.toml#L119-L121)). I advised the reporter to [patch the Dockerfile](https://github.com/matrix-org/synapse/issues/13849#issuecomment-1252647175) in order to get Synapse 1.61 built again.

We saw this manifest in the report below: a version of poetry-core was released under which previous versions of poetry would fail to build, see https://github.com/matrix-org/synapse/issues/13849#issuecomment-1252592401.

It seems like the Python packaging ecosystem doesn't have an obvious way to pin build-time dependencies. (See for instance https://discuss.python.org/t/pinning-build-dependencies/8363 or https://github.com/pypa/pip/issues/9542.) The best approach that I can see is described in https://github.com/pypa/pip/issues/9542#issuecomment-770388939, namely

- install the build-time dependencies into the environment you're interested in
- `pip install --no-build-isolation ...`

[^1]: The steps which run `apt-get update` and run the abitrary `sh.rustup.sh` script aren't reproducible either, if anyone's counting.
