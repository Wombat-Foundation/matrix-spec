#15334 introduced a bug where `HomeServer` instances no longer get garbage collected during `trial` test runs. As a result, memory usage grows to multiple gigabytes during test runs.

See https://github.com/matrix-org/synapse/pull/15334/files#diff-f50ec854a65082453f4086048f20c291ca6020fab973486a9da2285025394cc8R180.
When we garbage collect generation 0, `self.hs` still holds a reference to the `HomeServer`, which gets promoted to generation 1 and then never collected.

Apart from that, there are also a couple of other leaks at play.

---

- [x] Fix `HomeServer`s leaking due to not being GCed.
      https://github.com/matrix-org/synapse/pull/15630
- [x] Fix `FederationRateLimiter` (and referenced `HomeServer`s) leaking due to `_rate_limiter_instances` global.
      https://github.com/matrix-org/synapse/pull/15630
- [x] Fix config cache added in #15284 growing too large (~360 entries). `HomeServerConfig`s are pretty heavy and hold on to a lot of stuff, including Jinja templates. A suitable max size for the cache might be 8-16 entries.
      https://github.com/matrix-org/synapse/pull/15646
- [ ] Fix `HomeServer`s leaking via [synapse.util.caches.caches_by_name](https://github.com/matrix-org/synapse/blob/9bb2eac71962970d02842bca441f4bcdbbf93a11/synapse/util/caches/__init__.py#L39).
- [ ] Fix `HomeServer`s leaking via [synapse.util.caches.CACHE_METRIC_REGISTRY](https://github.com/matrix-org/synapse/blob/9bb2eac71962970d02842bca441f4bcdbbf93a11/synapse/util/caches/__init__.py#L37).
- [ ] Fix `HomeServer`s leaking via [synapse.config.cache._CACHES](https://github.com/matrix-org/synapse/blob/796a4b74823b721c72de07e45718f05e78e1565d/synapse/config/cache.py#L34).

The last 3 are fairly annoying to fix, so I've left them alone.
