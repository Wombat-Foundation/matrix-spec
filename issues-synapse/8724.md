**Description:**

I have a need to restrict publishing to the room directory to server admins only. The question was originally asked by @benparsons  about restricting room creation to server admins only and we were pointed in the direction of the Spam Checker API. For room creation, the spam checker API is [short circuited if the user is a server admin](https://github.com/matrix-org/synapse/blob/develop/synapse/handlers/room.py#L611). For directory publishing, the spam checker is [always consulted](https://github.com/matrix-org/synapse/blob/develop/synapse/handlers/directory.py#L412).

The `ModuleApi` that the spam checker receives doesn't appear to have direct, public access to `auth.is_server_admin` and #7331 suggests that I couldn't use the private [_auth](https://github.com/matrix-org/synapse/blob/develop/synapse/module_api/__init__.py#L50) in `ModuleApi` to do this as the spam checker isn't async. The other suggestion from #7331 to use `third_party_rules` also doesn't seem workable in this situation as [check_visibility_can_be_modified](https://github.com/matrix-org/synapse/blob/develop/synapse/events/third_party_rules.py#L126) (which is consulted late on in directory publishing) also doesn't know whether the user is an admin or not (unlike [on_create_room](https://github.com/matrix-org/synapse/blob/develop/synapse/events/third_party_rules.py#L79)).

Similarly [config.room_directory.is_publishing_room_allowed](https://github.com/matrix-org/synapse/blob/develop/synapse/config/room_directory.py#L134) doesn't know whether the user is an admin or not. I could update homeserver.yaml with a list of user ids that match the list of server admins, but that feels very redundant and not maintainable.

Am I reading & understanding this all correctly? If I submitted a PR to short-circuit the spam checker for admins in the case of directory publishing would that have a reasonable change of being accepted? Or is there another approach you'd prefer me to take?

Thanks
