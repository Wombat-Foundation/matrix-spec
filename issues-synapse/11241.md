[As discovered by @tulir](https://matrix.to/#/!SBYNQlpqkwJzFIdzxI:nevarro.space/$EyGLPHcogIusgKqMjLkWKVC6MOJpFtm-PFfOhtgrqG8?via=nevarro.space&via=beeper.com&via=matrix.org), when using the MSC2716 `/batch_send` endpoint, events specified in `state_events_at_start` will come down ~~incremental `/sync`~~ and the application services `/transactions` endpoints. Since this is historical state, it shouldn't be coming down the live pipe.

We already have a Complement [tests to ensure the historical messages don't come down incremental sync](https://github.com/matrix-org/complement/blob/11adc36c58c29c0603ded8a6276563276d2d5649/tests/msc2716_test.go#L258-L303), but we should also do the same for the state events.


### Relevant code

 - Where we create state events from the `state_events_at_start`: [`synapse/handlers/room_batch.py#L213-L249`](https://github.com/matrix-org/synapse/blob/a271e233e9f846193c22b6d74f33ae7d7f2c1167/synapse/handlers/room_batch.py#L213-L249)
 - `builder.internal_metadata.historical = True`: [`synapse/handlers/message.py#L608`](https://github.com/matrix-org/synapse/blob/a271e233e9f846193c22b6d74f33ae7d7f2c1167/synapse/handlers/message.py#L608)
 - If it's a historical event, then we mark it as `backfilled = True`: [`synapse/handlers/message.py#L1526-L1530`](https://github.com/matrix-org/synapse/blob/a271e233e9f846193c22b6d74f33ae7d7f2c1167/synapse/handlers/message.py#L1526-L1530)
