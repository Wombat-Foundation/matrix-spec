### Description

I've installed matrix-synapse on a server ( Ubuntu Server 16.04 LTS with a fixed IP ) which is accessed via a reverse proxy ( NGINX ).
The installation + reverse proxy configuration is done as described at https://github.com/matrix-org/synapse.
Now there is following issue, if I visit the server at port 8008 the matrix web interface is shown ( URL changes to 'http://domain-name:8008/_matrix/client/#/login' but if I visit 'http://reverse-proxy-domain-name' ( server name configured in NGINX ) only the welcome to NGINX page is shown.

So for testing purposes I've installed matrix-synapse + NGINX in a VirtualBox VM ( Ubuntu Desktop 16.04 LTS ).
The described issue persists. If I visit localhost:8008 the matrix web interface is shown ( URL changes to 'localhost:8008/_matrix/client/#/login' ) but if I visit 'matrix.whatever.private' ( as configured in the NGINX reverse proxy configuration ) only the welcome to NGINX page is shown.
If I type in manually 'matrix.whatever.private/_matrix' then the following message shows up:
'Method Not Allowed
Your browser approached me (at /_matrix) with the method "GET". I only allow the method HEAD here.'
Now I do not understand where the request using NGINX goes wrong.

Can you please explain how to configure the VirtualBox VM / remote-server correctly to get the reverse proxy working.
Please explain every step carefully because my experience with server administration is rather sparse.

### Edit

@neilisfragile ( 2018, Feb. 12th ):
I just moved the file from the conf.d folder to the sites-available folder and created a symbolic link in sites-enabled, then restarted nginx. It showed the same result.
PS: I'm pretty sure that nginx does read and use the conf.d configurations on Ubuntu as well. An easy way to proof my claim is to just comment out a single curly bracket in the matrix.conf file ( /etc/nginx/conf.d/matrix.conf ) and then call sudo nginx -t which checks the configuration for validity ( which now shows now an error: 'nginx [emerg] unexpected end of file, expecting "}" in /etc/nginx/conf.d/matrix.conf:10
nginx: configuration file /etc/nginx/nginx.conf test failed' ). If you now restart nginx ( sudo systemctl restart nginx ) and then try to access http://matrix.whatever.private Firefox says 'Unable to connect'.

### Solution ( for the git clone/pip installation only )

I added the following lines to the matrix.conf file:
    location = / {
        return 301 _matrix/client/#/login;
    }

If matrix is now accessed under matrix.whatever.private it gets redirected to matrix.whatever.private/_matrix/client/#/login and then the location /_matrix { } section does the reverse proxy stuff to the internal port 8008.
However this works only for the git clone/pip installation.
After configuring the same in a package-manager installation Firefox shows the error:
'No Such Resource
No such child resource.'

### Solution ( for the package-manager installation )
After some digging in the matrix installation process I found out that the web client is the [matrix-angular-sdk](https://github.com/matrix-org/matrix-angular-sdk) which does not get installed with the package-manager installation.
So one way would be to install the web client manually ( like in the repo description ) and place it at the correct position in the system. This approach seems risky because it is sort of reverse-engineering the matrix-synapse git clone/pip installation.
So the second way is to remove the package-manager installation and re-install matrix-synapse via git clone/pip.

### Minimal working nginx configuration file /etc/nginx/conf.d/matrix.conf
server {
    listen 80;
    server_name matrix.whatever.private;
    location = / { # This tells nginx to change the URL to http://matrix.whatever.private/matrix/client/#/login if http://matrix.whatever.private is accessed
        return 301 _matrix/client/#/login;
    }
    location /_matrix {
        proxy_pass http://localhost:8008
        proxy_set_header X-Forwarded-For $remote_addr;
    }
}
