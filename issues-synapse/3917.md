Currently may clients fail to set a canonical alias when you add one to a room (e.g. Riot/Web), as per the cluster over at https://github.com/vector-im/riot-web/issues/7339.  Rather than expecting all the clients to forget to do this, should the server try to set a canonical alias if the user has power to do so, and if one isn't already set?

Upsides:
 * You'll get consistent results across clients, rather than relying on the client implementers to get it right.

Downsides:
 * It's bit magical
 * What if the user didn't want to mark that alias as canonical?  (What's the use case for that though?)
 * Should DELETE /directory/room/$alias go and try to remove the canonical alias when that alias is deleted?
