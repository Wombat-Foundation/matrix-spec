### Description
According to the pushrules section of the client server spec at https://matrix.org/docs/spec/client_server/r0.6.1#m-rule-master, enabling the `.m.rule.master` should disable all default pushrules, but not any custom overrides. However, enabling this rule also disables custom overrides.

<!-- Describe here the problem that you are experiencing -->

### Steps to reproduce

- enable the `m.rule.master` pushrule
- create a custom override pushrule
- send an event that your custom pushrule should match on

The expected behavior would be for the user-defined pushrule to still fire, but it does not. Looking at the base definition for `.m.rule.master`, it doesn't make sense that the rule would be able to work as the spec describes, because you can't place a custom rule before a default rule, and this default rule will match everything.
