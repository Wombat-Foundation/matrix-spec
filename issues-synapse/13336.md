I don't like not-strict-by-default either. FWIW there is the intention to have that feature At Some Point (https://github.com/samuelcolvin/pydantic/issues/1098).

For enforcement, we could write a linter which parses the AST and complains if a type inheriting from `BaseModel` has an annotation which involves one of the non-strict types, or involves a [constrained type](https://pydantic-docs.helpmanual.io/usage/types/#arguments-to-conlist) without `strict=True`. I don't like the idea of writing something home-grown for that, but

- we don't want a repeat of stringy power levels
- maybe it wouldn't be too bad to write? Reminds be a bit of the mypy plugin...
