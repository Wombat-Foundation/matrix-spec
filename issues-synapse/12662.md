#### Description

While working on other features, I noticed that lots of (older) bits of synapse still do something like `logger.info("Error doing thing: %s", e)`, one such instance [here](https://github.com/matrix-org/synapse/blob/4337d33a73988763e27eb9450307084f8eab6f16/synapse/rest/media/v1/thumbnailer.py#L80).

All `logger` levels (including `info` and `debug`) allow providing `exc_info`, which prints the entire exception in the console as a traceback. However, if I understand sentry correctly, it will also give the exception in the correct format to sentry for ingest.

In that particular instance above, `%s` gave me no information about the error;
```
2022-05-06 20:31:40,552 - synapse.rest.media.v1.thumbnailer - 80 - INFO - GET-33 - Error parsing image EXIF information:
```

...with no lines before or after. I believe it would be a lot more debuggable with a traceback.
