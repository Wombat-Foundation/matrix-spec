### Description

I've tried every combination of `matrix.[domain]` that I can think of, including wildcards, `https://`, but no matter what I try, I always get `Failed to send event! (M_UNKNOWN: Can't create an ACL event that denies the local server)`.

The [documentation for this feature](https://spec.matrix.org/latest/client-server-api/#server-access-control-lists-acls-for-rooms) indicates that rules are applied in this order:

1. If there is no m.room.server_acl event in the room state, allow.
2. If the server name is an IP address (v4 or v6) literal, and allow_ip_literals is present and false, deny.
3. If the server name matches an entry in the deny list, deny.
4. If the server name matches an entry in the allow list, allow.
5. Otherwise, deny.

So, based on this documentation, I should be able to create a server ACL like this:

```
{
  "content": {
    "allow": [
      "matrix.[domain]",
      "*.onion"
    ],
    "allow_ip_literals": false
  }
}
```

...and yet I always receive the above error. I've double-checked for typos, ports, schemes, wildcards, nothing works.

### Steps to reproduce

- log into element as admin
- go to room where you want to apply the ACL
- type /devtools
- click "Explore Room State"
- click "Send Custom State Event"
- paste the following (replacing `[domain]` with your actual hs top-level domain):
```
{
  "content": {
    "allow": [
      "matrix.[domain]",
      "*.onion"
    ],
    "allow_ip_literals": false
  }
}
```

- see error message, no matter what you do: `Failed to send event! (M_UNKNOWN: Can't create an ACL event that denies the local server)`
