### Description

Since a few days, we're facing deadlocks (or some kind of stuck service) with synapse regularely. The deadlock happens at least once a day, starting with Oct 17th on no particular time (sometimes during daytime, sometimes late night, sometimes twice). Interestingly, Synapse magically self-heals itself after a few hours. On the other hand, neither restarting the containers or killing the database connection helps anything during the deadlock. Everything we can do is to wait. Here you see the CPU graph (all the dips that go close to 0 are deadlocks):

![2022-10-20T17:01:26,647933964+02:00](https://user-images.githubusercontent.com/25278864/196986234-f6eee5b9-71b7-46e7-8670-4934d8c99124.png)

Load on the system is fairly normal and goes down during the deadlocks. No obvious peaks in CPU, memory, disk I/O or network consumption or amounts of requests. Also, postgres database doesn't report any blocked transactions or something alike.

We already tried disabling dimension, federation, presence, but nothing helped with the issue.

Once the deadlock happens, the nginx reverse proxy and matrix-dimension start logging timeouts, but nothing relevant gets logged by Synapse itself. We already lowered the loglevel to `INFO`, but still nothing that caught our eyes.

During the deadlock a simple request to `localhost:8008/_synapse/admin/v1/server_version` might take up to 120 seconds before it gets replied.

We're a bit out of ideas how to further debug and isolate the root cause of the deadlocks, especially since Synapse doesn't log any errors at all. So any hints are highly appreciated.

We're running Matrix on Docker using the [matrix-ansible-docker-deploy](https://github.com/spantaleev/matrix-docker-ansible-deploy) playbook (with PostgreSQL database and nginx reverse proxy). The setup runs on a dedicated Debian Bullseye VM with 24GB RAM.

When the deadlocks started, we ran Synapse 1.68.0 already since a few weeks. So a Synapse upgrade can be ruled out as reason. On Oct 17th we upgraded Synapse to 1.69.0, but problems stayed.
