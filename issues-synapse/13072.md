We have a limit on the rate a user is allowed to send events, but it is applied quite late in the processing cycle (specifically, it happens in `persist_and_notify_client_event). 

That means we go to all the effort of getting a lock on the room, checking the state, building the event, making the request to the event persister - all to be told that the user is way over their ratelimit.

This means it's quite easy for a single user to overload an event creator worker with lots of /send requests.
