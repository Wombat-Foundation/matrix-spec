```py
self.clock.call_later(
    30, self.clock.looping_call, run_timeout_handler, 5000
)
```

Changing this to the following would avoid a bit of hassle when debugging (see below);

```py
self.clock.call_later(
    30, self.clock.looping_call(run_timeout_handler, 5000).start
)
```

Because `DelayedCall` implicitly expects a normal function/method to be passed to `call_later`, the `__repr__` function errors on the following line;

https://github.com/twisted/twisted/blob/65f382f43dfe9bec9d25d99ce0cb05db115f5fac/src/twisted/internet/base.py#L241

`L.extend((" ", self.func.__qualname__, "("))`

Functions have a `__qualname__`, but object instances doesnt.

When `DelayedCall.debug` is true (when debugging the reactor), it calculates a `repr` of itself on init, this means that *all* `DelayedCall`s go past that above line, which means that any `DelayedCall`s waiting on `LoopingCall` will error out.
