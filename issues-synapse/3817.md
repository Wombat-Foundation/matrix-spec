when we get an incoming transaction for a room we don't know about, we try to rebuild the room by recursively requesting state and auth events from other servers in the room.

In the past this has been seen as a bit of a hidden feature, because it helps resolve the mess for people who drop their databases. *However* the problem is that it can take literally days to rebuild that room while the server gradually requests events and server keys for the room, and meanwhile lots of other requests take ages to be handled, either because the slow transaction has a lock (eg the per-server transaction linearizer) or because the keyring request queue is being monopolised.

I think we should reject such transactions rather than bog synapse down trying to handle them
