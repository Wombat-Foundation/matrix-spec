It would be very helpful if the `user_mapping_provider` of `OIDC` would support the mapping of a bit more complex data structure.

For instance if the returned data would not be `user.id` but `user.data.id`.

So instead of ...
```
    user_mapping_provider:
      config:
        subject_claim: "id"
        localpart_template: "{{ user.id }}" 
        display_name_template: "{{ user.name }}"
        email_template: "{{ user.email }}"
```

it would require to be mapped like this...

```
    user_mapping_provider:
      config:
        subject_claim: "id"
        localpart_template: "{{ user.data.id }}" 
        display_name_template: "{{ user.data.name }}"
        email_template: "{{ user.data.email }}"
```

This would be more flexible.
