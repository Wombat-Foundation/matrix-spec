### Info:

Apparent problem with matrix federation

Matrix.org homeserver is on 1.20.0rc2 and newest live version (that I was able to pull with pip) is 1.19.1

Servers running 1.19.1 and older are unable to communicate to each other, but depending on what version they're on, they may or may not be able to communicate with the matrix.org homeserver. Version 1.17.0 has broken federation; no communication between other homeservers, or the matrix.org homeserver. My server running version 1.19.1 is able to communicate with the matrix.org homeserver, but no other homeservers.
Problem began saturday, september 12; This is when messages stopped transmitting between me and several people I know with a similar problem. Several other people running their own matrix servers have failed federation.

Federation tester shows affected servers as having valid federation, but communication between affected servers is not possible.

In one case, messages outgoing from https://mutualaid.work to https://mellow.zone were received, but messages from mellow.zone to mutualaid.work were not received. Initially, messages on mutualaid.work received from mellow.zone were marked as having gone through, but marked as "Unable to decrypt: The sender's device has not sent us the keys for this message" but then failed to be received at all, not even sending the "failed to decrypt" message in place of message attempts. Meanwhile, user on mellow.zone is receiving all messages from mutualaid.work.

Both mutualaid.work and mellow.zone servers are on synapse version 1.19.1

Watched server log while user on mellow.zone attempted to messageme, outgoing messages processed as expected, but no incoming messages or errors were received from mellow.zone user. Mellow.zone user reported their messages to mutualaid.work were timing out.
