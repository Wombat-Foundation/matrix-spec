If we have a forward extremity for a room as E, and you receive `A`, `B`, s.t. `A -> B -> E`, and `B` also points to an unknown event `X`, then we will request the state before `X` and do state res between that and the current state of the room. That is fine unless `X` is a state event, in which case it will get missed out of the resolved state.

(This is all *completely* broken due to #3923 at the moment, so is somewhat moot until that gets fixed)
