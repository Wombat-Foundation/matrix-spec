To carry over what was raised [here](https://matrix.to/#/!vcyiEtMVHIhWXcJAfl:sw1v.org/$LUehEb3JKlNza-6ymO-Qwjd5spM4v9OeFr1wdsTjd2A):

> Currently a module is instantiated via its `__init__` method, which (as a magic method) shouldn't really be async (as far as I know). What if we have a use-case that involves asynchronous initialisation of a module? E.g. Let's say we need to translate some non-local room aliases into room IDs on module initialisation and want to report an error (to Synapse) if that fails.

When I say "allowed to fail" (in the title), I mean similarly to how a module's `parse_config` static method may fail in a [controlled manner](https://github.com/matrix-org/synapse/blob/583f22780f44157c50bc2dc5c242e88cc18c7886/synapse/util/module_loader.py#L61-L66).
