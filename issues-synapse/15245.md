It seems like there is a bug somewhere that triggers this [codepath](https://github.com/matrix-org/synapse/blob/release-v1.78/synapse/storage/databases/main/event_federation.py#L241) or [this one](https://github.com/matrix-org/synapse/blob/release-v1.78/synapse/storage/databases/main/event_federation.py#L460), while there were not any upgrade/downgrade of synapse.

It then triggered really long state-res, on fed-inbound and persister workers:
![image](https://user-images.githubusercontent.com/1643573/224376621-ad51ac4f-4695-47d8-8f08-7b14ecfd2138.png)

@richvdh said about the fact that we need 2 state res on different workers:
> yes basically we need to do at least two state resolutions: one where we resolve across the predecessors of the new event to calculate the state at that event, and one where we resolve across the new forward-extremities to calculate the new current_state
