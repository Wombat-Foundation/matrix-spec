We should finish up implementation of Matrix 1.3, the first thing to do is to make a checklist of remaining tasks from the release notes (https://matrix.org/blog/2022/06/16/matrix-v-1-3-release#the-full-changelog):

----

## Client-Server API

* [x] Deprecate the `sender_key` and `device_id` on `m.megolm.v1.aes-sha2` events, and the `sender_key` on `m.room_key_request` to-device messages, as per MSC3700.
* [x] Make `from` optional on `GET /_matrix/client/v3/messages` to allow requesting events from the start or end of the room history, as per MSC3567.
* [x] Add refresh tokens, per MSC2918. #9450
* [x] Describe a structured system for event relationships, as per MSC2674.
* [x] Describe how relationships between events can be "aggregated", as per MSC2675 and MSC3666.

## Server-Server API

* [x] Add a destination property to the `Authorization` header, as per MSC3383. #11398

## Application Service API

* [x] Add timestamp massaging as per MSC3316. #11866

## Room Versions

* [x] Add room version 10 as per MSC3604. #13220
* [x] Update the default room version to 9 as per MSC3589. #12058

----

Other remaining things from above:

* [x] `/relations` returns an extra `original_event` field: #12930
  * See #14025.
