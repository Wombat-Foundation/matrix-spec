suppose I create a custom login type `com.example.login_token` (NB a [login type](https://matrix.org/docs/spec/client_server/r0.6.0#login) as opposed to a [UIA authentication type](https://matrix.org/docs/spec/client_server/r0.6.0#authentication-types)) 
and say that the login submission should look like this:

```
{
  "type": "com.example.login_token",
  "token": "<login token>"
}
```

I should be able to implement this via a custom password provider; however, synapse expects to see an `identifier` in the submission, and will reject the login before passing it to the password provider.
