Description

Splitting #4788 into separate issues. ACME challenge configured to port 8080 possibly ignores the port, listens on port 80. Error messages are unhelpful, problem unintuitive to debug. Follows #4871 during my testing of the 0.9 branch.  To reproduce, install accordingly to #4871, then add

```
tls_certificate_path: /etc/matrix-synapse/homeserver.tls.crt
tls_private_key_path: /etc/matrix-synapse/homeserver.tls.key
acme:
    enabled: true
    port: 8080
    url: https://acme-staging.api.letsencrypt.org/directory
    bind_addresses: ['127.0.0.1']
```

to the config ... acme-staging is used because the systemd unit **will try** to get the cert so many times, that acme blocks your test server from further requests due to too many requests.

to ensure that the container has port 8080 correctly exposed, i stopped synapse, installed nginx and reconfigured it to listen on port 8080. Browsing `http://matrix.vaizard.xyz:8080/.well-known/acme-challenge/deZVII6Wyso5bAsgJkiFrHDUcf-zeqe4IGCD55ylQLU` gave me a nice 404 error with a nginx banner.

**I suppose that this is can be a major reason for the bad adoption rate of the acme certs** - a lot people have their homeserver behind a reverse proxy. Since the acme challenge ignores the port configuration, nobody ever gets their certificates, as long as they have a similar setup to mine.
