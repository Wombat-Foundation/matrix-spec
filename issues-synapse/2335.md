Sample case: riot-android stacks up initial sync requests due to client side timeouts (https://github.com/vector-im/riot-android/issues/1413). This eventually leads to a large number of ongoing calculations that have the potential to bring down the server due to resources (RAM, mostly).

Instead of recalculating everything on every new request, synapse should stop processing the canceled request (including postgres queries). Ideally however, instead of canceling the request it should continue processing the request but not start new calculations when the same request comes in.

For example: 
* Client initial syncs
* Client times itself out
* Client initial syncs again - Don't start fresh, just block on the first request and wait for it to finish
