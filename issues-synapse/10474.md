I'd like to have a liveness probe endpoint (e.g. under `/liveness` or `/alive`) similar to the already existing readiness probe endpoint (`/health`). The liveness probe should only return an error if there's a problem within the synapse instance. Thus, when handling a liveness probe, synapse doesn't need to (and shouldn't) check any external components such as the database.

### Motivation

Using the liveness probe, operators can (automatically) restart the synapse instance if there's a problem within the instance. Errors in external components, such as the database, can not be recovered from by restarting synapse, so using the existing readiness probe endpoint (`/health`) would lead to unnecessary restarts.
