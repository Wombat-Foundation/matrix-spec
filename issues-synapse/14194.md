### Description

When running a docker image, you can watch logs of output printed(usually to /dev/stdout) by running a `docker logs container_name`. For some reason, when using the Dockerfile-workers build, you can see the output that is logged from start.py but not configure_workers_and_start.py.

### Steps to reproduce

- run docker image built from Dockerfile-workers tagged as synapse, add a `-e SYNAPSE_WORKER_TYPES=omgIneedWORKERZ` as an obvious example of an incorrect worker type
- look at output from `docker logs <container_name>`

### Homeserver

My homeserver, and Complement CI test runs

### Synapse Version

1.69.0rc2

### Installation Method

Docker (matrixdotorg/synapse)

### Platform

Docker Engine on linux with python 3.10.8

### Relevant log output

```shell
[admin@matrix2 ~]$ docker logs synapse

Generating a random secret for SYNAPSE_MACAROON_SECRET_KEY
Generating synapse config file /data/homeserver.yaml
Generating log config file /data/log.config
Setting ownership on /data to 991:991
2022-10-14 23:59:25,368 INFO Included extra file "/etc/supervisor/conf.d/synapse.conf" during parsing
2022-10-14 23:59:25,368 INFO Set uid to user 0 succeeded
```

### Anything else that would be useful to know?

I expected to see:
```
[admin@matrix2 ~]$ docker logs synapse
Generating base homeserver config
Generating a random secret for SYNAPSE_REGISTRATION_SHARED_SECRET
Generating a random secret for SYNAPSE_MACAROON_SECRET_KEY
Generating synapse config file /data/homeserver.yaml
Generating log config file /data/log.config
Setting ownership on /data to 991:991
omgIneedWORKERZ is an unknown worker type! It will be ignored
Starting supervisord
2022-10-15 00:09:39,165 INFO Included extra file "/etc/supervisor/conf.d/synapse.conf" during parsing
2022-10-15 00:09:39,165 INFO Set uid to user 0 succeeded
```
If this log output isn't being sent, no one will know if the system couldn't find libjemalloc.so.2, misspelled a worker_type or committed some other error while declaring variables to pass to the container during startup.
