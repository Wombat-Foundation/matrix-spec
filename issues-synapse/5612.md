## Description

eg, mail logs include:
```
2019-07-03 06:55:30 Connection from [10.0.0.0.1] refused: too many connections
```

I think we would do well with a limit on the count of SMTP connections running in parallel, even if this means that a temporary queue of emails builds up.

We definitely shouldn't fire and forget, especially for things like password resets, which seem to go through similar code, and while are unlikely to themselves hit a parallel connection limit, would fail if they were to be triggered within the same time window as a large email push is going on.
