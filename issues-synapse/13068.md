If you're trying to send events faster than the ratelimit allows, the first thing we do is slow down how quickly we process your requests. However, the apdex measurement includes requests that were slowed down in this way, so a single user trying to send a large number of events can cause the apdex measurement to fall.

I'm not entirely sure that this tarpitting behaviour is helpful. Shouldn't we just return a 429 straight away?
