... making the federation_reader chew all the CPU.

`filter_events_for_server` attempts to fetch all `m.room.member` events for each state group. However, the state group cache only has the concepts of "complete cache" and "individual keys"; so even though it may have all `m.room.member` events, it does not know this, and goes back to the db to pull out all 26000 or so member events, for each request.
