In order for [MSC3440](https://github.com/matrix-org/matrix-doc/pull/3440) to be successful it proposes being explicit about the behavior in [MSC2675](https://github.com/matrix-org/matrix-doc/pull/2675) that the `/relations` API should include the bundled relations of each returned event.

The behavior here was changed a few times:

* #5595 asked to include the original event (in the `original_event` field), which was done in #5626. Both of these fields included bundle aggregations (which is a bit odd since you're requesting the relations).
* #5654 stopped bundling aggregations in both the original event *and* the relations events.

The proposal here is to include them on the relations event. Note that #5654 includes the following:

> We also do this when pulling the relation events as well, because edits of edits are not something we'd like to support here.

The code in question lies at:

https://github.com/matrix-org/synapse/blob/1f9d0b8a7a6a777d59fe3217724f3e2ddb94a9b2/synapse/rest/client/relations.py#L232-L237

Which asserts that we don't allow relations to relations, but I don't think this is accurate. If this is a problem for edits we might need to solve this a different way.
