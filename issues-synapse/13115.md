### Description

We have our Azure AD connected to Synapse via OIDC. The `oidc_providers` config is almost the same as in the [sample config](https://matrix-org.github.io/synapse/latest/openid.html#microsoft-azure-active-directory).

One user changed her last name and therefore we changed the name in Azure AD. Afterwards, this happened:
- The user had E2EE-errors
- The secure key backup was not accepted anymore
- ~~A new account was created for the user~~
 
~~We did not expect this to happen, because the subject-identifier which is referred to in the config as `subject_claim` and defaults to `sub` should not have changed with renaming the user in Azure AD.~~

See [Synapse config_documentation](https://github.com/matrix-org/synapse/blob/develop/docs/usage/configuration/config_documentation.md#oidc_providers)
See [Microsoft OIDC reference](https://docs.microsoft.com/en-us/azure/active-directory/develop/id-tokens#payload-claims)

### Steps to reproduce

- Use Azure AD as SSO provider via OIDC
- Configure it as described in [sample config](https://matrix-org.github.io/synapse/latest/openid.html#microsoft-azure-active-directory)
- Create a user
- Sign into synapse, use the account
- *Everything works fine until now*
- Rename the user in Azure AD

Now:
- ~~A new user is created~~
- The user has E2EE problems
- ~~Sign into the new account does not work via SSO (probably, because old account is still linked to SSO?)~~
