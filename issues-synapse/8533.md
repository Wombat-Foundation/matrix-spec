### Description

Since upgrading to Synapse 1.21.1 we are experiencing irregular spikes (each for 15-30 seconds) in CPU usage of the main process (other workers are not affected).  
Prometheus metrics ("cpu usage by background jobs") show the job `send_dummy_events_to_fill_extremities` using all CPU (around 150%, but that seems to be a another bug?) at the time of the spike.

### Steps to reproduce

Sorry, not really reproducible. Happened 7 times in the 5 hours since the upgrade.

The only related log message I found was
```
matrix-synapse[39254]: synapse.handlers.message - 889 - WARNING - send_dummy_events_to_fill_extremities-0 - Denying new event <FrozenEventV3event_id='$yfeXUEgJ6XGNX3Kok8YoyN4gmRaDUGvSTC4qE7ugz6k', type='org.matrix.dummy_event', state_key='None'> because 403: You don't have permission to post that to the room. user_level (0) < send_level (50)
```
Other things I noticed happening at the time of the last hang
- The request and eviction rates of the `*getEvent*` cache skyrocket
- "per-block metrics" show `resolve_state_groups_for_events` and `state._resolve_events` each using ~150% CPU
- "Total DB usage by block" shows a spike in db usage from ` _fetch_event_list` about a minute before the CPU spike, then another spike from `resolve_state_groups_for_events` and `state._resolve_events` at the time of the CPU spike.

### Version information

- **Homeserver**: matrix.kif.rocks
- **Version**: 1.21.1
- **Install method**: deb Package
- **Platform**: Container (LXC) with Ubuntu 20.04.1 on a Proxmox host `Linux kif-matrix 5.4.65-1-pve #1 SMP PVE 5.4.65-1 (Mon, 21 Sep 2020 15:40:22 +0200) x86_64 x86_64 x86_64 GNU/Linux`
