### Description

There's a regression in how Synapse responds to changing the `/sync` filter whilst using an existing sync token.

### Steps to reproduce

- Call `/sync` with a filter set to ignore all events, and without a sync token
- Next, call `/sync` with the sync token received in the previous step, but with a (different) filter set to accept everything

Describe how what happens differs from what you expected.

- Previously, the second step would return an error as if the sync token didn't exist.

- Currently, the call to /sync succeeds, but no events are ever received, implying that the new filter didn't take.

- (Ideally, in future, one could expect this to just work, but right now this is probably a regression.)
