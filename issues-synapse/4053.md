### Description
I have because of creating tags using Quaternion for some rooms broken m.tag events in the rooms account_data. I tried to use the `DELETE /_matrix/client/r0/user/{userId}/rooms/{roomId}/tags/{tag}` Endpoint to remove the broken events but even after Synapse does return HTTP 200 the tag event is still there. 

So first of all it should NOT return 200 in this case and second it should be able to resolve that (It basicly breaks the usage of my account...).

The account_data generated by creation looks like this:

```
"account_data": {
          "events": [
            {
              "content": {
                "tags": {
                  "m.favourite": {
                    "order": 0.2817608267132813
                  }
                }
              },
              "type": "m.tag"
            },
            {
              "content": {
                "tags": {
                  "m.favourite": {
                    "order": ""
                  },
                  "Freifunk": {
                    "order": ""
                  }
                }
              },
              "type": "m.tag"
            }
          ]
        },
```

### Steps to reproduce

1. Create custom tags using quaternion 0.0.9.2 for a room
2. Try to delete them
