### Description

Synapse should prevent users ingoring themselves.

Apart from obvious reasons it also causes various really weird and hard to identify problems. 
Also related to https://github.com/vector-im/element-meta/issues/410

### Analysis
@anoadragon453  kindly analysed the case, quote follows.

Synapse does do processing specific to ignored users when modifying account data: https://github.com/matrix-org/synapse/blob/af795173bec447da44b65b739d05d0083b02229d/synapse/storage/databases/main/account_data.py#L525-L530

But only data that will be inserted into the ignored_users table is potentially blocked. And that does not include checking for ignoring the requester.

Awkwardly, I've noticed that even though we do maintain this ignored_users table, we don't actually use it. We always just pull from account data anyways:

https://github.com/matrix-org/synapse/blob/64ec45fc1b0856dc7daacca7d3ab75d50bd89f84/synapse/handlers/sync.py#L1613-L1634
https://github.com/matrix-org/synapse/blob/4c2096599c9780290703e14df63963e77d058dda/synapse/visibility.py#L89-L91
When events are filtered, there is also no exemption for the current user: https://github.com/matrix-org/synapse/blob/4c2096599c9780290703e14df63963e77d058dda/synapse/visibility.py#L131-L132
