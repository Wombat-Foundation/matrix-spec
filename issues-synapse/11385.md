### Description

<!-- Describe here the problem that you are experiencing -->

With previous versions of Synapse, the following command generated a default homeserver.yaml in `/tmp/z` belonging to the current user. This is critical for using Synapse in CI.

```sh
$ mkdir /tmp/z
$ docker run -it --env UID=`id -u` --env GID=`id -g ` --rm
   --mount type=bind,src=synapse-data,dst=/data,src=/tmp/z
   -e SYNAPSE_SERVER_NAME=my.matrix.host
   -e SYNAPSE_REPORT_STATS=yes
   matrixdotorg/synapse:latest generate
$ ls -lah /tmp/z/homeserver.yaml
-rw-r--r-- 1 yoric yoric 91K nov.  18 10:12 z/homeserver.yaml
```

With 1.47.0, the files are created as `root`:

```sh
$ mkdir /tmp/z
$ docker run -it --env UID=`id -u` --env GID=`id -g ` --rm
   --mount type=bind,src=synapse-data,dst=/data,src=/tmp/z
   -e SYNAPSE_SERVER_NAME=my.matrix.host
   -e SYNAPSE_REPORT_STATS=yes
   matrixdotorg/synapse:latest generate
$ ls -lah /tmp/z/homeserver.yaml
-rw-r--r-- 1 root root 91K nov.  18 10:13 z/homeserver.yaml
```

That's not desirable. In particular, in my case, this entirely breaks my ability to run Synapse for integration tests on modules.

### Regression

I believe that the regression was added in the following patch: https://github.com/matrix-org/synapse/commit/0b99d4c8d219aca3f8a0e4f3542bb67dfc016420#diff-d0e0d1fe01e659a4debf8bf6d66912cfafb1aa1d88537f03686f789af4c94c92 .
