The current method of providing Matrix notifications is outlined [here](https://matrix.org/docs/spec/push_gateway/unstable.html). That's reasonable for a generic protocol. 

However, many users refuse to have non-free software (e.g. GCM/APNS) on their devices; or an internal network using a Matrix system might restrict internet connectivity. A fallback should be required for these cases. This can be pretty straightforwardly implemented via HTTP/2 (see the IETF RFCs).

So, the instead of having to leave the homeserver, go through an external push gateway, then an external push provider, then to the client (the method in the spec to do it via GCM or APNS), Synapse should have its own webpush implementation (and ideally, it should be included in the matrix push spec). 

Not only will it solve the issues mentioned above, but it means that Riot, for example, no longer has to drain battery life through polling!

Further, it would set a good reference implementation for the matrix push spec

Web push RFC specs: https://datatracker.ietf.org/wg/webpush/documents/
