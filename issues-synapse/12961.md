**Motivation**

Allow to easily pass secrets into synapse such as DB connection, registration_shared_secret, etc and allow easy dynamic configuration.

**Description:**

At the moment synapse supports some configurations when started with the "generate" command. It is however impossible to create a customised configuration with it, if unsupported parameters need to be changed.

To work around this, at ungleich we moved the configuration file to /config-ro and update it prior to starting synapse like this:

```
            - "mkdir -p /config; sed \"s,SECRETPOSTGRESPASSWORD,$POSTGRES_PW,\" /config-ro/homeserver.yaml > /config/homeserver.yaml && /start.py run"
```
However as you can see, this a) requires specific configuration support (very similar to the generate command) and b) is somewhat limited/gets unreadable for many options.

**Existing solution**

Instead of doing one-by-one, we suggest to add support for configuration options similar to what mattermost is doing: It resembles the yaml tree by using underlines in the variables:

```
            - name: MM_SERVICESETTINGS_SITEURL
              value: "https://{{ tpl .Values.fqdn . }}"
            - name: MM_BLEVESETTINGS_INDEXDIR
              value: "/mattermost/bleve-indexes"
```

This way arbitrary points in the configuration file can be set.

For synapse, some variables already include underlines, so we might need to escape that or parse for section names so that ambiguities are not existing.

**Proposal**

Add a configuration parser that for each known section/configuration looks for the corresponding environment variable and if it exists, sets the variable *after* applying the values from the configuration file.

Environment variables which are set, but empty, should be interpreted as either "unset this option" or "set it to empty". This part needs a bit of discussion, as we handle `federation_domain_whitelist` a bit special in regards to `empty`. 
The `federation_domain_whitelist` setting might be handled by literaly using SYNAPSE_FEDERATION_DOMAIN_WHITELIST='[]' and keeping the "empty = unset" behaviour, but I am not sure if we have other similar, a bit special cases.
