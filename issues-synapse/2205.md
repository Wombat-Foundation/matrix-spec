The `api/v1/register` endpoint allowed registration to happen with[ type: m.login.password](https://github.com/matrix-org/synapse/blob/master/synapse/rest/client/v1/register.py#L260). 

 `r0` explicitly does not support this since [_check_password](https://github.com/matrix-org/synapse/blob/master/synapse/handlers/auth.py#L496) only applies to existing users. 

There is now a two-stage process involving a 401 and a `session_id` returned in the 401 error message (I'm actually not convinced using `401` as a step in an Authentication flow is proper use of the HTTP Status code), at any-rate this seems to be inline with the [Interactive Authentication API](http://matrix.org/docs/spec/client_server/r0.2.0.html#user-interactive-authentication-api) - the problem, is that this particular request should be *non-interactive* there are no additional user interaction steps which are required to be taken but the API has simply been made more complicated for flows such as this one. 

There is some documentation missing (https://github.com/matrix-org/matrix-doc/issues/912) but the current flow as inferred from Riot looks like this:

To give another idea of how obtuse this is, here for example is what `/register` looked like in  python for the `api/v1` endpoint:

```py3
# Really that's it!
def register_with_password(username, password):
    return api._send("POST", "/register",
        {"type":"m.login.password", "user": username, "password": password})
```

Here is what it would have to look like for if we were going to switch to the `r0` endpoint:
```py3
def r0_register_with_password(username, password):
    session_id = None
    try:
        api._send("POST", "/register",
            {"user": username, "password": password}
        )
    except MatrixRequestError as e:
        # We need to get the session_id out of the 401 error message
        if e.code === 401:
            import json
            content = json.loads(e.content)
            if 'session' in content:
                session_id =  content['session']
            else:
                raise e
    api._send("POST", "/register", {
        "auth": {
            # I have no idea why we use this flow which is normally used for guests
            # or where it is documented
            "type": "m.login.dummy",
            "session": session_id
        }
    })
```
