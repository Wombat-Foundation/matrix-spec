Possibly as two different endpoints. Users should be able to leave - this is just for an admin bootstrapping groups.

This is for FOSDEM.

Proposed endpoints (for server admins, **not** group admins):
* `POST /_synapse/admin/v1/groups/+group:example.org/join/@user:example.org` (empty request body)
  * Only works for force-joining local users to local groups. Fails with error otherwise.
  * If the group is invite only then the group admin implicitly invites the user before doing the join.
* `POST /_synapse/admin/v1/users/@user:example.org/groups/+group:example.org/update_publicity` (request body of `{"publicise":true}` to match self-serve group API)
  * Also only works for local users, though remote groups should be possible given this sort of setting doesn't touch the actual group object. Fails with error otherwise.

Possible alternatives:
* An appservice which has full control over the entire user space and can then impersonate each user on its own.
  * Not great because users might briefly still receive an invite to the group while the appservice does the second request, which might fail. This could result in a momentary bing noise.
