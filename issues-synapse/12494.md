### Description

We use `ldap_auth_provider.LdapAuthProvider` as password provider for synapse. If someone tries to log in to our synapse
instance with a capitalized local part of the user ID the operation seems to succeed but the server returns an invalid user ID
and the provided macaroon token is not recognized later on.

### Steps to reproduce
- Prerequisites
  - Synapse Server with `ldap_auth_provider.LdapAuthProvider` as password provider
  - Matrix Client which makes no consistency checks on a given user ID (i.e. Element Web Version 1.10.7)
- Try to log in with a valid user ID, but capitalize some or all of the letters
   ```JSON
   {
     "type": "m.login.password",
     "password": "XXX",
     "identifier": {
       "type": "m.id.user",
       "user": "TEST"
     },
     "initial_device_display_name": "matrix.uni-marburg.de (Firefox, Linux)"
   }
   ```
   This seems to succeed and the server returns an `access_token`. But note that the `user_id` contains the unaltered 
  local part of the user ID as given by the user.
   ```JSON
   {
     "user_id": "@TEST:matrix.uni-marburg.de",
     "access_token": "syt_TmFnZWxmcg_QJUOneAbKBZtoXHhKKlC_0lvgyI",
     "home_server": "matrix.uni-marburg.de",
     "device_id": "LJPAAHKWEF",
     "well_known": {
       "m.homeserver": {
         "base_url": "https://matrix-homeserver.uni-marburg.de/"
       }
     }
   }
   ```
  Subsequent requests of the client fail with the following error message:
   ```JSON
   {
     "errcode": "M_UNKNOWN_TOKEN",
     "error": "Invalid macaroon passed.",
     "soft_logout": false
   }
   ```

I would expect the synapse server to either implicitly convert the user id to lowercase or fail the login immediately
with a meaningful error message that the user ID is invalid.
