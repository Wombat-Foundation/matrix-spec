I've seen this on and off over the years but not got a good example until now:

jcgruenhage.xyz tries to send a PDU to charity.az, but charity.az fails to resolve for unknown reasons (it has no SRV, but the A record seems fine, and even has valid TLS via LetsEncrypt on port 8448):

```
2017-11-04 12:52:41,071 - synapse.http.matrixfederationclient - 212 - WARNING - - {PUT-O-182552} Sending request failed to charity.az: PUT matrix://charity.az/_matrix/federation/v1/send/1509694103843/: TimeoutError([Query('_matrix._tcp.charity.az', 33, 1)],)
2017-11-04 12:53:14,113 - synapse.http.outbound - 236 - INFO - - {PUT-O-182552} [charity.az] Result: 401 Unauthorized
```

However, the reason this ends up being a `401 Unauthorized` seems to be because the synapse ends up connecting to itself rather than charity.az:8448:

```
2017-11-04 12:53:14,087 - synapse.access.https.8448 - 59 - INFO - PUT-227888- 46.5.14.151 - 8448 - Received request: PUT /_matrix/federation/v1/send/1509694103843/
2017-11-04 12:53:14,088 - synapse.crypto.keyring - 122 - DEBUG - PUT-227888- Verifying for gruenhage.xyz with key_ids ['ed25519:a_FcsH']
2017-11-04 12:53:14,088 - synapse.crypto.keyring - 758 - DEBUG - PUT-227888- Got key ed25519:a_FcsH ed25519:a_FcsH for server gruenhage.xyz, verifying
2017-11-04 12:53:14,089 - synapse.federation.transport.server - 181 - ERROR - PUT-227888- authenticate_request failed
2017-11-04 12:53:14,089 - synapse.http.server - 123 - INFO - PUT-227888- <SynapseRequest at 0x7fae3f97c7a0 method=PUT uri=/_matrix/federation/v1/send/1509694103843/ clientproto=HTTP/1.1 site=8448> SynapseError: 401 - Invalid signature for server gruenhage.xyz with key ed25519:a_FcsH
2017-11-04 12:53:14,089 - synapse.access.https.8448 - 91 - INFO - PUT-227888- 46.5.14.151 - 8448 - {None} Processed request: 1ms (1ms, 0ms) (0ms/0) 105B 401 "PUT /_matrix/federation/v1/send/1509694103843/ HTTP/1.1" "Synapse/0.24.1"
```

This ends up with the 'authenticate_request' error in the log, and some extreme confusion as to why synapse would be trying to connect to itself (and be unable to authenticate its own cert).
