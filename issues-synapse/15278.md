Synapse modules have the ability to register an endpoint resource in order to handle incoming HTTP requests (added in https://github.com/matrix-org/synapse/pull/10062, [see example module usage](https://github.com/matrix-org/synapse-email-account-validity/blob/b9cd3afbf56138756d72e2c27aaa4fa3f7753b86/email_account_validity/account_validity.py#L62-L65)).

https://github.com/matrix-org/synapse/blob/53680ae148b4f35d69f5c6bbf779b6cec49a7c04/synapse/module_api/__init__.py#L464-L478

This is a really handy feature! However, they are currently able to register an endpoint under any path... which seems like it will be prone to breakage as we expand the matrix spec and `/_synapse/...` endpoints.

Say a module hardcodes listening on the path `/_synapse/client/register_jwt_token` into its workflow. If in the future Synapse decides that it would like to listen and handle that path itself, this module will suddenly break.

I propose that modules should only be allowed to register resources on a path with a prefix that would not conflict with anything we add in the future, i.e. `/_synapse/module/...`.

I can't currently think of any valid use cases for modules to register an endpoint outside of `/_synapse/module/`. A module may want to register `/_matrix/client/unstable/...` in order to implement an MSC, but the typical approach we take is to implement that in Synapse, and then provide a module callback.

To prevent future headaches, I suggest we minimize the scope of paths that can be registered by:

- Warning in the upgrade notes that we will be disallowing registering module endpoints under any path that does not start with `/_synapse/module` (for example). This gives some time for module developers to shout about any valid use cases.
- After a suitable amount of time has passed, raise an exception if a module does try to register anything outside of `/_synapse/module`.

This would be a breaking change for any existing module that registers a web path other than `/_synapse/module`, which is likely currently every module that calls `synapse.module_api.register_web_resource`.
