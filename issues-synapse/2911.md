### Description

Debian 8, Certbot (from their git), installing Synapse from the matrix provided debian repositories
and following the Matrix Synapse/LetsEncrypt configuration guide available at https://matrix.org/docs/guides/lets-encrypt.html fails to produced a working system.

"journal -xn" reveals that matrix is attempting to read the files, but it cant not due to perms errors.
- matrix python[3480]: OSError: [Errno 13] Permission denied:'/etc/letsencrypt/live/${myhostdom}/privkey.pem'

This is caused by Synapse starting as a non-root user as the files in /etc/letsencrypt are perms 600 and not readable by the matrix-synapse user.

Work around is to copy the files to another dir  where they can be chown'd to the matrix-synapse user while keeping them chmod'd to 600. 

This will break auto-updating of the certificate material with certbot and will require additional coding to work around.

In an ideal world, synapse would start with the correct permissions to read things like this, then afterwards drop permissions that were no longer required. (this is like how apache, nginx etc start up as root so they can read configs, bind to ports <1024 etc, then drop permissions to their normal service user as to not expose the system to hack attempts).
