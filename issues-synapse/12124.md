### Description

I decided to try out HAproxy as Synapse reverse proxy. It looks like the [advised configuration](https://github.com/matrix-org/synapse/blob/develop/docs/reverse_proxy.md#haproxy) sends an incorrect IP with X-Forwarded-For, at least if your server supports both IPv4 and IPv6. It seems to "append" v6 address to your v4 address. I'm assuming this will cause problems with black-/whitelisting and such.

![image](https://user-images.githubusercontent.com/100730729/156256129-245bcf36-e577-471a-8b48-dd9a037297c3.png)

Also visible on HAproxy logs

![image](https://user-images.githubusercontent.com/100730729/156256673-629265fe-9ea2-4561-8420-e11522b8d336.png)



### Steps to reproduce

- Install Synapse
- Install HAproxy 2.5.4
- Follow the reverse proxy instructions [here](https://github.com/matrix-org/synapse/blob/develop/docs/reverse_proxy.md#haproxy)
- Start up Synapse and connect.

Expected behavior: Client and server being reported with a correct IP address, not this "v4 + v6 hybrid".

### Fix

I just followed the instructions here instead: [LINK](https://discourse.haproxy.org/t/make-haproxy-stop-prepending-to-ipv4-addresses-in-x-forwarded-for/3368)

Instead of:
`frontend https`
`  bind :::443 v4v6 ssl crt /etc/ssl/haproxy/ strict-sni alpn h2,http/1.1`
`  [...]`

...use this:
`frontend https`
`bind *:443,:::443 v6only ssl crt /etc/ssl/haproxy/ strict-sni alpn h2,http/1.1`
`[...]`

(and do the same for the federation port if needed)

Reverse proxy now forwards correct IPv4 and IPv6 address to Synapse. 

Perhaps the guide should be updated?
