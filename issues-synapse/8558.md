### Description

As the title mentions, the password based user interactive auth seems to require a top level `user` field in the `auth` field.
I haven't checked the other user interactive auth types, but at least the password based one requires this.

### Steps to reproduce

After doing a request that requires user interactive auth the server returns this 
```json
{
    "flows": [
        {
            "stages": [
                "m.login.password"
            ]
        }
    ],
    "params": {},
    "session": "sboloUTeNsVdqMtuoJdBniSV"
}
```
We now create the same request but provide authentication info, for example, for a [delete_devices](https://matrix.org/docs/spec/client_server/latest#post-matrix-client-r0-delete-devices) request:
```json
{
    "auth": {
        "identifier": {
            "type": "m.id.user",
            "user": "example"
        },
        "password": "wordpass",
        "session": "sboloUTeNsVdqMtuoJdBniSV",
        "type": "m.login.password"
    },
    "devices": [
        "ACJOOAHTKD"
    ]
}
```

This fails with a 400 status code, bad request, the body for the response is as follows:
```json
{
    "errcode": "M_MISSING_PARAM",
    "error": ""
}
```

After double checking the spec for a missing parameter in my request I decided to see what Element does:
```json
{
    "devices":["JBUVJRJFBT"],
    "auth":{
        "session":"YTVZEVtoLTVcQYkTcpPLSIgP",
        "type":"m.login.password",
        "user":"@example:localhost",
        "identifier":{
            "type":"m.id.user",
            "user":"@example:localhost"
        },
        "password":"wordpass"
    }
}
```

Notice the additional user field, adding this field indeed makes the previous request succeed. As far as I can tell this isn't required, nor mentioned in the [UIAA section of the spec](https://matrix.org/docs/spec/client_server/latest#password-based).
