**Description:**
I'm sure there's a good reason for allowing public access to the profile API calls but if one tries to keep them private, problems arise.

- Say I know that a user that nicks `dudebro` in other internet presences.
- Say I know the HS of `dudebro` or that I simply want to probe whether this is the case

1. I'd then check `/_matrix/client/r0/profile/%40dudebro%3Ahomeserver.bro`
2. If I get a hit, there's no way of stopping me from using the value of `avatar_url` to gain access to `dudebro`'s avatar image by enter it into the well-known public media path of the synapse server: `https://homeserver.bro/_matrix/media/v1/thumbnail/homeserver.bro/AVATAR_URL?width=800&height=800

In the context of private HS instances, user expectancy is definitely that sensitive data such as avatars or even just displaynames are kept private. Since I assume this publicness has to do with federation I suggest an option to limit this exploit.
