**Link to problem area**:

https://spec.matrix.org/v1.12/client-server-api/#tracking-the-device-list-for-a-user

**Issue**

The spec says:

> Periodically, Alice’s client stores the `next_batch` field of the result from [/sync](https://spec.matrix.org/v1.12/client-server-api/#get_matrixclientv3sync) in persistent storage. If Alice later restarts her client, it can obtain a list of the users who have updated their device list while it was offline by calling [`/keys/changes`](https://spec.matrix.org/v1.12/client-server-api/#get_matrixclientv3keyschanges), passing the recorded `next_batch` field as the `from` parameter. If the client is tracking the device list of any of the users listed in the response, it marks them as outdated. It combines this list with those already flagged as outdated, and initiates a [/keys/query](https://spec.matrix.org/v1.12/client-server-api/#post_matrixclientv3keysquery) request for all of them.

... but won't that return just the same information as calling `/sync` with the `next_batch` token (which we will presumably do anyway)?

I don't get it. Which is a particular shame, given [I wrote it](https://github.com/matrix-org/matrix-spec-proposals/pull/894).
