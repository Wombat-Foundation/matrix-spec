**Issue**
What is wrong?

The spec says you can't make a thread based on a reply:

> It is not possible to create a thread from an event which itself
> is the child of an event relationship (i.e., one with an `m.relates_to`
> property). It is therefore also not possible to nest threads.

But Element Web allows threads to be created with replies as thread root:

![image](https://github.com/matrix-org/matrix-spec/assets/76812/d68d6b95-1f98-42dd-a3df-5777a99c2d1c)

**Expected behaviour**

I think the spec should probably allow replies to be thread roots - I don't see any harm in it.

So the wording might become:

> It is not possible to nest threads: you are not allowed to create a thread
> from an event which itself is in a thread (see ... for the exact definition of
> when an event is in a thread).

This would allow any event except one that is in a thread to become a thread root, including reactions, edits etc. We might want to restrict it to just replies, but that seems a little messy.

This sentence, later in the same section would also need rewording:

> As shown, any event without a `rel_type` can become a thread root by simply referencing it
> using an `m.thread` relationship.

Maybe to:

> As shown, any event **not in a thread** can become a thread root by simply referencing it
> using an `m.thread` relationship.
