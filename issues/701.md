We describe SHOULD as strongly recommended, and occasionally forget to use the right case in doing this. When we use the wrong case we tend to mean one of two things: the right case, or that previously established context is being furthered clarified. 

An example is the fallback representation of replies: clients MUST include a fallback when they support rich replies, and they are required to use the plain text fallback format. The sentence which follows, 'the formatted_body should use the following template' is not actually making the template a strong recommendation, it's saying that given the plain text format previously described, the result of the HTML format for the same event would be the following. Should is the right word in this case, but extremely hard to understand. We shouldn't have the spec be cryptic.
