* Open a new tab in firefox and navigate to https://spec.matrix.org/v1.1/client-server-api/#fallback-for-mtext-mnotice-and-unrecognised-message-types
* The browser loads the page and scrolls to the right place in the viewport. Some font faces are not loaded.
* After some time, fonts fail to load and we fall back to some default. (I noticed hundreds of content security policy warnings in the javascript console about not being able to load a remote resource from an inline style. What the heck are we trying to do?)
* Doing so recalculates layout. The main content of the page shifts. I am no longer looking at the anchor that I wanted to link to.
* Mild irritation, apply aloe vera and take deep breaths.

I make two conjectures:

1. I reckon that if we used a font that was available on the system, we wouldn't have this two-step loading which scrolls the viewport away from the intended destination fragment. See e.g. https://systemfontstack.com/
2. https://developer.mozilla.org/en-US/docs/Web/CSS/overflow-anchor/Guide_to_scroll_anchoring refers to Firefox's "scroll anchoring" behaviour. Turning on the debug `layout.css.scroll-anchoring.highlight` tool option I see that the scroll anchor is the table of contents. Not sure why this happens; I guess firefox has some heuristic here. We can opt out of this behaviour with the css `.td-sidebar { overflow-anchor: none; }`. I reckon that doing this would also help avoid the jumpy behaviour.
