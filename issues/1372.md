This was brought up a while ago, and I hoped to have time to address it - that has not been the case. 

Context: the [SAS Emoji](https://spec.matrix.org/v1.5/client-server-api/#sas-method-emoji) are used in verification, and the spec references a "common translation" being available from this repo. Those translations are meant to be updated from time to time, but we tend to forget - it should become part of the release process.

The translations are specified on Element's weblate instance (https://translate.element.io/projects/matrix-doc/sas-emoji-v1/) and stored in-tree on our repo: https://github.com/matrix-org/matrix-spec/tree/main/data-definitions

The weblate git repo is extraordinarily confused as it doesn't understand what happened when some force pushes happened to the matrix-doc (now spec-proposals) repo. It needs manually unpicking on the weblate side with a lot of git magic.

Once fixed on the weblate side, we should ensure a point gets added to the release process to synchronize the translations - this would be the exact same process Element Web uses to ship (Lock, Commit, Push, Merge PR on github, Pull, Unlock).
