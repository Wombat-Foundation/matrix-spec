In November 2023, a XMPP (Jabber) instant messaging protocol encrypted TLS connection wiretapping (Man-in-the-Middle attack) of [jabber.ru (aka xmpp.ru) servers were discovered](https://notes.valdikss.org.ru/jabber.ru-mitm). To this day there wasn't any sufficient measures done for Matrix homeservers to prevent such attacks.

The attacker can issue new TLS certificates using Let’s Encrypt service by hijacking unencrypted traffic, which then can be used to hijack encrypted HTTPS connections to homeserver using transparent MiTM proxy.

Due to this attack vector, here's some of my suggestions to the Spec:

1) Add separate section of security considerations regarding Matrix API, with best practices (enabling HSTS and rate-limiting endpoints) and requirements (making HTTPS mandatory instead of "recommended").

2) Research feasibility of supporting [RFC 6698](https://datatracker.ietf.org/doc/rfc6698/) (The DNS-Based Authentication of Named Entities (DANE)). Some of the additional advantages of this is providing alternative to certificate pinning (which is generally frowned upon), allowing secure federation over air-gapped networks and encouraging use of HTTPS for test environments.
