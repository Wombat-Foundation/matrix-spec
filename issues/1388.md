**Description:**

Please note, this is Matrix specification extend proposal.
Referring to: https://spec.matrix.org/v1.5/client-server-api/#mtext

Notification (eg. play a sound when a new message arrive) is desired but not always require for all messages in a room where automatic notifications is enabled.

Example, certain types of bot messages do not require notifications. 

Notifications on messages where notifications are not applicable, makes those messages a nuisance.

I propose a message-level notification control property, hypothetically named notification, where message sender controls the notifications.

If the notifications are enabled for a room, and:
1. If notification is true for the message, then client should render the notification (eg. play a sound).
2. If notification is false for the message, then client should not render a notification.

If the notifications are NOT enabled for a room:
3. Regardless of notification is true or false for the message, client should not render a notification.
