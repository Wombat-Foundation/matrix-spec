The Server Access Control List room state event and functionality announced by matrix-org/matrix-spec-proposals#1383 utilizes large JSON arrays within the content of a single event type with `state_key=""`. This design is inferior to a granular approach.

The shortcomings of formatting events in such a manner are well detailed by matrix-org/matrix-spec-proposals#1130. These large single state events with `state_key=""` add complications to the specification and implementations:
- Client authors must properly respect the existing list contents to update the event intuitively (through the event interface). This is subject to the ABA problem.
- Additional endpoints have to be designed and specified to manipulate the list content if the former point is to be mitigated similarly to `m.room.aliases`.
- This is still subject to the ABA problem between servers even if the former point mitigates ABA between clients.
- The authorship of entries in the ACL list is hard to track. A single state event only has one sender and one timestamp indicating the last update. It is slow and difficult to conduct a larger trace of all ACL event overwrites in room history to determine the time and author of each entry in the latest list. Clients in practice simply provide an inferior UX which gives the impression the latest sender is the whole list's author.
- The maximum size of a single event limits the list. While the limit has been reasonable in practice, it is only quite barely. Consider an ideal 65536 bytes available; consider some domain/entry length of 64 bytes: `65536 / 64 = 1024`. Consider 256 byte entries: `65536 / 256 = 256`. Finally consider matrix-org/matrix-spec#390 halving those limits when two entries are required to match every one. These numbers are not quite astronomical to reach.

#### Solution

The solution is to simply take a granular approach and design events that respect the key-value-store nature of the matrix room state system as intended. In this case, the `m.room.server_acl` event with `state_key=""` should be deprecated and `m.room.server_acl` events with `state_key="target.domain"` should emerge.
