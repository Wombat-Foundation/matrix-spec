Some services may wish to opt out of prividing a URL preview, perhaps for practicality or privacy reasons. An example being a webhook service not wishing to trigger when the hook URL is provided in a room (ref https://github.com/matrix-org/matrix-hookshot/issues/395).

Right now, the way this is avoided is by looking at the User Agent for each homeserver implementation and filtering on that, but this will only serve to fragment the ecosystem going forwards.

I'd suggest a simple header like `X-Matrix-Preview` be included on requests to allow services to tailor their responses.
