**Link to problem area**: https://spec.matrix.org/unstable/client-server-api/#mroompower_levels

**Issue**:

The spec says:

> The level required to send a certain event is governed by `events`, `state_default` and `events_default`. If an event type is specified in `events`, then the user must have at least the level specified in order to send that event. If the event type is not supplied, it defaults to `events_default` for Message Events and `state_default` for State Events.

But a few paragraphs down it also says:

> The power level required to invite a user to the room, kick a user from the room, ban a user from the room, or redact an event sent by another user, is defined by `invite`, `kick`, `ban`, and `redact`, respectively. Each of these levels defaults to 50 if they are not specified in the `m.room.power_levels` event, or if the room contains no `m.room.power_levels` event.

Yet `m.room.member` is also a State Event so this paragraph could be taken to be in contradiction to the earlier one.

This is a separate but related issue to #1019 since they both touch the PL defaults. However, I suspect that in this case the intent really was to special-case handling of `m.room.member` defaults and not have those events default to `state_default`. I think this is also what all current HS implementations do.

So I'm guessing we just want to be a bit more specific in the first quoted paragraph and make it say something like this instead:

> The level required to send a certain event is governed by `events`, `state_default` and `events_default`. If an event type is specified in `events`, then the user must have at least the level specified in order to send that event. If the event type is not supplied, it defaults to `events_default` for Message Events and `state_default` for State Events *other than `m.room.member`*.
