Many place blanket bans of all known dynamic DNS providers during spam waves. This can actually cause the collateral damage of Mjolnir banning users within various rooms who had been present for a long time and having built up good reputation.

We would need a way to mark subdomains with good reputation as _allowed_, while at the same time also marking any other subdomain of the parent domain as _denied_.

With the present syntax, the sole workaround would be to leave the deny key empty and list each and every known matrix home server within the `allow` key, but that does not scale.

https://spec.matrix.org/latest/client-server-api/#server-access-control-lists-acls-for-rooms
