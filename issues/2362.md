**Link to problem area**: 

* https://spec.matrix.org/v1.18/client-server-api/#mroompolicy
* https://spec.matrix.org/v1.18/client-server-api/#getwell-knownmatrixpolicy_server

**Issue**

*This is essentially a repeat of https://github.com/matrix-org/matrix-spec/issues/2060 but for policy servers.*

The spec and MSC both said "unpadded base64", but the first implementation only ever used URL safe unpadded base64, which bled into stable event types because of copy/paste.

Policyserv uses URL safe unpadded base64: https://github.com/matrix-org/policyserv/blob/88fc8a3b80397afea6f15104cd16c79c0db42e4b/homeserver/api_basic_server_info.go#L65

Through a series of references, Meowlnir uses standard base64: https://github.com/mautrix/go/blob/5dd21bedfc0f5f7a030b86421aa71f9ed6cec7be/id/crypto.go#L108

As of writing it's unclear if the spec should say "URL safe unpadded base64" or if the implementations should fix themselves. The consequence so far has been Ruma getting caught on the "invalid" base64, but other implementations/readers are seemingly okay.

Noticed because the Foundation's rooms have a `-` in its public key.
