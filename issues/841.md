**Link to problem area**:
https://matrix.org/docs/spec/client_server/r0.6.1#get-matrix-media-r0-download-servername-mediaid
and
https://matrix.org/docs/spec/client_server/r0.6.1#get-matrix-media-r0-download-servername-mediaid-filename

> **Response headers:**
> 
> Parameter | Type | Description
> -- | -- | --
> Content-Disposition | `string` | The `fileName` requested or the name of the file that was previously uploaded, if set.

**Issue**
What is wrong?
It suggests to write:
```
content-disposition: Screenshot_2021-05-29_12.24.32.png
```

The result is that people with clients that show these not inline but as links that you are expected to open in a browser. This is probably most common when bridging to IRC.

**Expected behaviour**
```
content-disposition: inline; filename=Screenshot_2021-05-29_12.24.32.png
```

Synapse already does the right thing. Conduit does not, and that's how @timokoesters and I found the issue.

Link to spec: https://datatracker.ietf.org/doc/html/rfc6266#section-4 

Yes, it's a seperate document, so it's technically not even the HTTP spec we're violating but the Internet is weird like that.
