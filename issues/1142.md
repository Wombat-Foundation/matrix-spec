**Link to problem area**: https://spec.matrix.org/v1.3/client-server-api/#mroommember

**Issue**
There was [this spec clarification](https://github.com/matrix-org/matrix-spec-proposals/pull/3730) that says that `invite -> knock` is allowed according to the auth rules.

Now I look at the [auth rules](https://spec.matrix.org/unstable/rooms/v10/#authorization-rules) (rule 5.7.3) and I get this reconstituted sentence if I pick the correct parts:

> If (the new) membership is `knock` and if the current membership is **not** `invite`, allow.

Which means `invite -> knock` should be rejected.

**Expected behaviour**
This part of the clarification should be reverted with this action not allowed, like before.
