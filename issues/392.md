[According to the OpenAPI 3](https://swagger.io/specification/#schemaObject), in a schema object,

> type - Value MUST be a string. Multiple types via an array are not supported.

[This github issue indicates that this was always the intention with OpenAPI v2](https://github.com/OAI/OpenAPI-Specification/issues/458), for "type" parameters to only be a string and not a list of strings.

There are many type fields in the swagger spec that are a list of strings which is not valid Swagger according to intentions of spec's author. This caused an issue for me recently when trying to use a tool to interact with the swagger (https://github.com/Trax-air/swagger-parser). Here's where I first ran into this issue as an example: https://github.com/matrix-org/matrix-doc/blob/6a3d68b7ed5560195bcadd9bbd05677cc69cd14f/event-schemas/schema/m.room.member#L32

While I understand that according to the letter of OpenAPI v2, the swagger spec is valid, at least one implementation chokes on it. The best solution to this of course is to upgrade the swagger to OpenAPI v3. @anoadragon453 what's the status of matrix-org/matrix-spec-proposals#1446?
