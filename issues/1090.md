**Link to problem area**: https://spec.matrix.org/v1.2/server-server-api/#get_matrixfederationv1make_joinroomiduserid (200 response)

> Event Template:  An unsigned template event. Note that events have a different format depending on the room version - check the room version specification for precise event formats.
> 
> Name | Type | Description
> -- | -- | --
> content | Membership Event Content | Required: The content of the event.
> origin | string | Required: The name of the resident homeserver.
> origin_server_ts | integer | Required: A timestamp added by the resident homeserver.
> sender | string | Required: The user ID of the joining member.
> state_key | string | Required: The user ID of the joining member.
> type | string | Required: The value m.room.member.
> 

**Issue**: I understood this to mean that there would be no `prev_events` and no `auth_events` in the event template. As Rich demonstrates here, that is not the case.

> ./scripts-dev/federation_client.py -c ../../config/homeserver.yaml '/_matrix/federation/v1/make_join/!vcyiEtMVHIhWXcJAfl:sw1v.org/@a:sw1v.org?ver=9' 2>/dev/null | jq .
> ```

Some specific complaints:

1. AFAICS this isn't just a proto-event or an event template, but a complete PDU in its own right?
2. The joining server is expected to alter this event after the fact:
   > Once the joining server has the room ID and the join candidates, it then needs to obtain enough information about the room to fill in the required fields of the m.room.member event. It obtains this by selecting a resident from the candidate list, and using the GET /make_join endpoint. The resident server will then reply with enough information for the joining server to fill in the event.
    >
    > The joining server is expected to add or replace the origin, origin_server_ts, and event_id on the templated event received by the resident server. This event is then signed by the joining server.

   Since the format of the event differs between room versions, I think strictly speaking the details of what customisation is required belongs in the details of each room version.
3. On that theme: the text quoted immediately above says that the joining server should generate an event_id. But that only applies to rooms v1 and v2.
