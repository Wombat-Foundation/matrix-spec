**Link to problem area**: https://spec.matrix.org/v1.13/client-server-api/#peeking_get_matrixclientv3events

**Issue**

If the request doesn't include a `room_id` it cannot work for peeking because the homeserver wouldn't know which room to watch.

In Synapse, the `room_id` [is required on this endpoint for guests](https://github.com/element-hq/synapse/blob/59a15da43364c6b3319983e68f686750a918ec9a/synapse/rest/client/events.py#L57-L59). If the user is not a guest, [this logic](https://github.com/element-hq/synapse/blob/59a15da43364c6b3319983e68f686750a918ec9a/synapse/notifier.py#L820-L830) is used to determine the room(s) to watch: if there is no explicit `room_id` the rooms that are joined by the user are watched, which is the behavior of the non-peeking version of the endpoint.

Construct only supports the peeking version of this endpoint and [requires a room ID](https://github.com/matrix-construct/construct/blob/0624b69246878da592d3f5c2c3737ad0b5ff6277/modules/client/events.cc#L112-L116).
