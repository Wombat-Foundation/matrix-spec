C2S-OpenAPI does [specify](https://github.com/matrix-org/matrix-doc/blob/master/data/api/client-server/tags.yaml#L67) the room tag format (currently, only the number `order`).

**Issue**
Synapse doesn't enforce the room tag format. If a client does set an invalid room tag with setRoomTag (order is a string, for example), the server does return this invalid tag to clients, making the homeserver ifself non-conforming.
Dendrite and Conduit reject invalid room tags in setRoomTag, but such data can be set with setAccountDataPerRoom anyway. If getRoomTags is used then, Dendrite and Conduit respond with 500 (Internal Server Error), but is this helpful?

**Expected behaviour**
The C2S-spec should mention that room tags should conform to the [m.tag](https://github.com/matrix-org/matrix-doc/blob/master/data/event-schemas/schema/m.tag.yaml#L20) definition, but not duplicate (and enforce) this definition inside the C2S spec.
