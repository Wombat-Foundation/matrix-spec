**Describe the bug**
The example given for `GET /_matrix/client/r0/rooms/{roomId}/members` (as rendered at https://matrix.org/docs/spec/client_server/r0.6.1#get-matrix-client-r0-rooms-roomid-members) contradicts the spec.

for `state_key` the spec says: "The user_id this membership event relates to. In all cases except for when membership is join, the user ID sending the event does not need to match the user ID in the state_key, unlike other events. Regular authorisation rules still apply."

while the example has `"sender": "@example:example.org"` and `"state_key": "@alice:example.org"` for a `join` `membership`. Probably because templates are used to create the example.
