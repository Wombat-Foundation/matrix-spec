It currently unclear how long a Matrix client should attempt to remain compatible with older spec versions. It is often not easy to keep compatibility around forever, but other side, it's unclear when it might be safe to remove.

To assist client developers, it would be nice to have suggested (informational) client backwards compatibility policy somewhere on the spec site. For example, something like "clients are suggested to keep compatibility with previous API versions for N months".

MSC2844 (currently in review) [makes some statements](https://github.com/matrix-org/matrix-doc/pull/2844/files#diff-b507892ecc3c4ba4b16106c235fc66019de7571d5772b8942acef24e1a8ed0f5R250-R252) about this, so if the suggestions it contains end up merged, perhaps that is sufficient.
