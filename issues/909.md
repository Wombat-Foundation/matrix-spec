We previously had a warning saying that the viewer was looking at an old version of the spec, and the new spec platform has support for this idea, but it isn't fully integrated. 

How we build the spec for release is to essentially snapshot it and upload that whole artifact, but if we were to change the design or mark that version as outdated then we'd need to rebuild the whole thing and re-upload the snapshot. This quickly becomes a non-trivial task to make a minor edit.

The issue is further complicated by nodejs being notoriously bad at being stable for the future: if in N years we need to make a sweeping CSS change, we'll have to dig out that old version of the spec and re-build it. Assuming the dependencies aren't backwards compatible (which is common after 2+N years), we'd be stuck trying to find N year old dependencies to rebuild the thing.

Currently, the approach is to declare bankruptcy and just not have warnings on old versions, but this is obviously not ideal for the long term. The spec release process builds an artifact of the spec with the "this is not the latest version" warning, but mostly intended as a backup to defeat the dependency problem: if we continue to snapshot releases, then we'll have a snapshot of what the spec looked like as not-latest as well. 

Some solutions which could work to solve this are:
1. Copy/paste the entire spec to a `/v1.1` folder at release so the site builder can intrinsically build all versions with the latest styling. This is not great because spec authoring becomes N times more difficult as trying to locate a section of text means wading through the old versions. Some editors might be able to get by with a gitignore entry for the versioned directories, with force-adding to git being how we accomplish their inclusion in the repo.
2. Decide that older versions aren't going to get CSS fixes and are effectively static (current choice). We can likely figure out a pipeline for deploying that "now not the latest version" warning artifact over top of the warning-less version.
