There might be a mismatch between the specification for [spec for login fallback](https://matrix.org/docs/spec/client_server/r0.6.1#login-fallback) and implementation(s). The specification says:

> If a client does not recognize any or all login flows it can use the fallback login API:
>
>   GET /_matrix/static/client/login/
>
> This returns an HTML and JavaScript page which can perform the entire login process. The page will attempt to call the JavaScript function `window.onLogin` when login has been successfully completed.

Synapse's implementation seems [to call `window.matrixLogin.onLogin`](https://github.com/matrix-org/synapse/blob/236d2d699d48e15d3c16ebd82dc8473a2fff8aca/synapse/static/client/login/js/login.js#L42), which is then [used by Riot iOS](https://github.com/vector-im/riot-ios/blob/bec5ed590d0330e3932df3ad110fc92ea72b84df/Riot/Modules/Home/Fallback/AuthFallBackViewController.m#L41-L47) and [Riot Android](https://github.com/vector-im/riot-android/blob/f73c3b6613bb1710d39f12a3a557dfc833ba0fa6/vector/src/main/java/im/vector/activity/FallbackAuthenticationActivity.kt#L170-L175).

(Riot Web and RiotX Android don't seem to use the fallback functionality, as far as I've been able to determine.)

I do not believe that Dendrite or Ruma supports fallback login. Not sure about other homeserver / client implementations.
