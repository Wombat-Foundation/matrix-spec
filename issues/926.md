I remember the idea of "adding as friends" on matrix to be a complex one, mentioned a few times in a few MSCs over here. (Though I can't remember which ones)

I think some proposals to the idea have been quite complicated, but i'd like to propose a simpler version; Relationship Tags.

Each 'relationship' is simply a tag user A can put on user B, and vice versa.

Then these tags could have scoped visibility, like so;
- Private (Only A)
- Shared (A and B)
- Public (publicly fetchable)

If these tags could carry additional data or not (using the tag as it's key to a KV store), I'm not entirely sure.

---

This could make implementing "friends" incredibly easy, as both users would only have to set a `m.friend` relationship tag (in shared mode) on eachother, and clients/libraries/etc. can recognise these users as "friends".

Tagging ignored or blocked could be easy as well, by putting `m.friend.ignored` or `m.blocked`. (Though how the latter one interacts with existing blocking mechanisms wouldn't be entirely clear.)

---

This system can easily expand beyond just friendship tagging, future extension might be additional visibility modes, like such;
- Common (like Shared, but fetchable for C by A if C has a two-way relationship of the same type to B)
- Restricted (like rooms-restricted to spaces, relations could only be fetched if someone is part of a space)
