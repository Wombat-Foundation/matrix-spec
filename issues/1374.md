**Link to problem area**: https://spec.matrix.org/v1.5/client-server-api/#presence, https://spec.matrix.org/v1.5/client-server-api/#post_matrixclientv3useruseridfilter and https://spec.matrix.org/v1.5/client-server-api/#get_matrixclientv3sync

**Issue**
This came up while I was triaging https://github.com/matrix-org/complement/pull/563's changes compared to the spec: Nowhere in the spec it is made explicit if existing users' presence should be sent during initial sync.

As far as I know, sytest does not assume this, and the tests I converted pertaining it only go over presence updates made while the user is already sharing a room and doing incremental syncs, not about "existing presences" when the user is doing an initial sync.

However, the spec is ever-so-vague about this, only noting "Presence events are sent to interested parties where users share a room membership.", which does not make it clear when it should be sent.

In the most broad case, this implies that all presence events should be sent during initial sync, but that has obvious performance drawbacks, and so i'd like for this to be noted explicitly, if this indeed intended behaviour.
