**Issue**

Hello,

I have a question about the Matrix Megolm session key backup algorithm.

Suppose Alice wants to join a Megolm session in which Bob is participating. If I understand correctly, at a high level the protocol works as follows:

1. Alice generates a `Curve25519` key pair, signs her public key with her device-signing key, and uploads the public key together with its signature using: `POST /_matrix/client/v3/room_keys/version`

2. Bob fetches Alice's backup public key and signature via: `GET /_matrix/client/v3/room_keys/version`. He verifies the signature, generates an ephemeral `Curve25519` key pair, and performs `ECDH` with Alice's public key to derive a shared secret. He then derives an encryption key and a `MAC` key, uses them to encrypt and authenticate the Megolm session key, and uploads the ciphertext, authentication tag, and his ephemeral public key via: `PUT /_matrix/client/v3/room_keys/keys`

3. Alice downloads the encrypted key material using: `GET /_matrix/client/v3/room_keys/keys` She derives the same symmetric keys, verifies the authentication tag, and decrypts the Megolm session key.

In this protocol, Bob is not authenticated to Alice. As a result, it seems that Alice could be tricked into joining the wrong (malicious) room without noticing. Is this by design? Am I missing something?

Thanks
