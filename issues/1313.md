Verification messages can be sent either in a room shared by the two parties.
There is a part not covered in the documentation that is signicantly different between to_device and room.

It's when requesting (`m.key.verification.request`), the requests is sent to several devices (as several to_device or as one room message).
The spec says
> When Bob[..] accepts the verification on one of his devices (sending [..] an m.key.verification.ready [..]), Alice will send an m.key.verification.cancel event to Bob’s other devices with a code of m.accepted [..].

<img width="771" alt="image" src="https://user-images.githubusercontent.com/9841565/199020620-1084ff96-2fc7-45e0-bc3e-7b645417ffef.png">


This actually only applies to to_device verification.

If the verification is performed in a room, no cancel event should be sent at all when the request is readied.
Instead Bob's other devices when seeing a `m.key.verification.ready` sent from another of bob's own device should enter a passive mode and stop interacting with this verification at all (to prevent sending cancel for unexpected events).
