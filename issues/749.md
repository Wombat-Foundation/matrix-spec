The following (not conclusively exhaustive) list has timestamps of `integer` type with no specified `format`. When `format` is not specified, [Swagger](https://github.com/OAI/OpenAPI-Specification/blob/master/versions/2.0.md#data-types) falls back to [JSON Schema](https://tools.ietf.org/html/draft-zyp-json-schema-04#section-3.5) for type definitions. JSON Schema [conveniently says](https://tools.ietf.org/html/draft-zyp-json-schema-04#section-5.5) that integers should be distinguished from floating-point numbers, and stops at that.

The conclusion from the above is that we should be clear which `integer` is used in each particular place. This issue is about timestamps, which should always be `int64`. The question is - do we need an MSC here or would a _clarification_ be enough.
- [client-server/notifications.yaml](https://github.com/matrix-org/matrix-doc/blob/82a4a028bd523d8ac9b5c46ff4b58cbbe47e998e/api/client-server/notifications.yaml#L126)
- [event-schemas/schema/m.receipt](https://github.com/matrix-org/matrix-doc/blob/82a4a028bd523d8ac9b5c46ff4b58cbbe47e998e/event-schemas/schema/m.receipt#L29) (this one defines `ts` as `number`, not following JSON Schema's spirit; but there's no way to specify precision in JSON Schema so perhaps it's safer to leave it as is).
