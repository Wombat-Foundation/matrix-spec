

This room version builds on [version 1](/rooms/v1) with an improved
state resolution algorithm.

## Client considerations

There are no client considerations introduced in this room version. Clients
which implement the redaction algorithm locally should refer to the
[redactions](#redactions) section below for a full overview of the algorithm.

## Server implementation components

> **Note:** 
The information contained in this section is strictly for server
implementors. Applications which use the Client-Server API are generally
unaffected by the details contained here, and can safely ignore their
presence.

Room version 2 uses the base components of [room version 1](/rooms/v1),
changing only the state resolution algorithm.

### Event format

Events in rooms of this version have the following structure:

### Definition `Persistent Data Unit`
```typescript
type PersistentDataUnit = {

  /**
  * The ID of the user sending the event.
  * @example "@someone:matrix.org"
   */
  sender: string;

  /**
  * Timestamp in milliseconds on origin homeserver when this event was created.
  * @example 1234567890
   */
  origin_server_ts: number /* int64 */;

  /**
  * Event type
  * @example "m.room.message"
   */
  type: string;

  /**
  * If this key is present, the event is a state event, and it will replace previous events
  * with the same `type` and `state_key` in the room state.
  * @example "my_key"
   */
  state_key?: string;

  /**
  * The content of the event.
  * @example {"key": "value"}
   */
  content: {};

  /**
  * Content hashes of the PDU, following the algorithm specified in [Signing Events](/server-server-api/#signing-events).
  * @example {"sha256": "ThisHashCoversAllFieldsInCaseThisIsRedacted"}
   */
  hashes: {

    /**
    * The hash.
    * @example "ThisHashCoversAllFieldsInCaseThisIsRedacted"
     */
    sha256: string;
  };

  /**
  * Signatures for the PDU, following the algorithm specified in [Signing Events](/server-server-api/#signing-events).
  * @example {"example.com": {"ed25519:key_version:": "86BytesOfSignatureOfTheRedactedEvent"}}
   */
  signatures: {};

  /**
  * Additional data added by the origin server but not covered by the `signatures`.
  * @example {"key": "value"}
   */
  unsigned?: {

    /**
    * The number of milliseconds that have passed since this message was sent.
    * @example 4612
     */
    age?: number;
  };

  /**
  * Room identifier.
  * @example "!abc123:matrix.org"
   */
  room_id: string;

  /**
  * The event ID for the PDU.
  * @example "$a4ecee13e2accdadf56c1025:example.com"
   */
  event_id: string;

  /**
  * For redaction events, the ID of the event being redacted.
  * @example "$def456:matrix.org"
   */
  redacts?: string;

  /**
  * The maximum depth of the `prev_events`, plus one. Must be less than the
  * maximum value for an integer (2^63 - 1). If the room's depth is already at
  * the limit, the depth must be set to the limit.
  * @example 12
   */
  depth: number;

  /**
  * Event IDs and reference hashes for the authorisation events that would
  * allow this event to be in the room.
  * 
  * Must contain less than or equal to 10 events. Note that if the relevant
  * auth event selection rules are used, this restriction should never be
  * encountered.
   */
  auth_events: {}[][];

  /**
  * Event IDs and reference hashes for the most recent events in the room
  * that the homeserver was aware of when it made this event.
  * 
  * Must contain less than or equal to 20 events.
   */
  prev_events: {}[][];
};
```
